# 系统架构

状态：**GATE_2_APPROVED_BASELINE**  
基准日：2026-08-14（Asia/Shanghai）  
性质：候选架构蓝图，不构成技术选型、采购、部署或编码授权。

## 1. 架构结论

推荐 Gate 2 审核一条“可替换端、可替换供应商、单编排、模块化单体”的候选基线：

1. 客户端以移动现场体验为中心，H5 与微信小程序都通过统一应用契约访问后端；先用 PoC 决定首发载体，不锁定。
2. 服务端优先采用模块化单体候选，不提前拆微服务；按领域模块隔离数据与权限，保留未来独立扩展边界。
3. 地图采用“公共道路服务 + 景区授权内部网络”两层模型，仅通过已核验入口连接。
4. AI 采用受控单编排器与少量只读工具；事实、路线和状态由确定性服务提供，模型只做理解、提取、解释和候选。
5. 结构化事实、来源证据、内容版本、资产权利、审核和有效期是核心数据，不是文档备注。
6. 数据模型从第一天带 scenic_area_id 做逻辑隔离，但首期只启用一个景区，不建设多景区 SaaS 后台。
7. 所有高风险能力都必须可降级：定位转手动到点，语音转文字，主题地图转标准地图，实时状态失败转“无法核验 + 官方渠道”。

## 2. 目标与非目标

### 2.1 本架构要支持

- 从有权处理的游记或自然语言需求提取地点、时间和约束，并保留原文证据；
- 让用户完成 POI、入口、交通方式和路线确认；
- 在真实二维地图执行公共道路与景区内部路线；
- 前台定位或手动到点后播放已审核讲解；
- 保存行程、轻量打卡，并以私有或链接方式分享；
- 让景区运营和文化审核人员维护版本化地理、开放状态、内容和资产；
- 对来源、许可、审核、发布、过期、撤回和删除形成完整审计链；
- 未来复制到其他景区时复用模块和契约，而不是复制六祖镇硬编码。

### 2.2 本阶段明确不设计为首发能力

- 全 3D 数字孪生、AR 寻宝、完整剧情游戏；
- 公开社区、排行榜、商城、直播、支付或导游内容售卖；
- 全镇全域连续步行导航；
- H5 锁屏或后台持续导航承诺；
- 长时麦克风监听、情感陪伴或多 Agent 自主执行；
- 自建全国底图、全国路由或完整多景区 SaaS 控制台。

## 3. 系统上下文与信任边界

| 参与者/系统 | 主要任务 | 信任边界 |
|---|---|---|
| 游客端 | 浏览、导入需求、确认行程、现场导览、问答、打卡、保存/分享 | 用户输入、游记、位置和语音均视为不可信且可能含个人信息 |
| 运营端 | 维护景区、POI、内部网络、状态、讲解和下架 | 需要实名账号、角色授权、双人或分级审核 |
| 文化/宗教审核人 | 判断事实类型、来源支持、措辞与场所边界 | 只能审核授权范围内内容，操作全量留痕 |
| 地图供应商 | 底图、POI 候选、公开道路路线等 | 输出是供应商数据，不等于景区现场事实；许可和缓存受合同限制 |
| 模型/RAG/语音供应商 | 结构化、检索辅助、生成或语音能力 | 不可信执行域；输入最小化、输出必须校验、供应商可替换 |
| 景区权威状态源 | 开放、封闭、活动、安全、设施等 | 必须明确责任人、有效期和更新 SLA；无源即不可声称实时 |
| 对象存储/CDN/消息服务 | 授权媒体、分发、异步通知 | 只存权利已清晰资产；权限、地域、删除和日志需审计 |

## 4. 候选逻辑分层

| 层 | 模块 | 责任 | 禁止越界 |
|---|---|---|---|
| 体验层 | 游客端、运营审核端 | 展示、输入、确认、无障碍和降级 | 不直接持有第三方密钥；不自行认定路线/事实 |
| 接入层 | API 网关/BFF、身份、限流、版本协商 | 统一鉴权、景区上下文、幂等、审计、错误规范 | 不承载文化生成逻辑 |
| 应用编排层 | 行程、导览会话、分享、受控 AI 编排 | 串联领域服务和只读工具，维护流程状态 | 不绕过领域校验或执行有副作用的模型指令 |
| 领域层 | 景区目录、GIS 路由、知识内容、运营状态、资产权利、用户行程 | 承担确定性业务规则与审核发布 | 模块间不得直接读写对方私有表 |
| 适配层 | 地图、模型、检索、语音、存储、通知适配器 | 统一供应商差异、坐标、超时、配额和故障 | 不把供应商对象直接暴露为内部权威对象 |
| 数据与审计层 | 事务数据、空间数据、检索索引、对象存储、审计/指标 | 版本、一致性、生命周期、备份、追溯 | 不把检索索引当事实源；不将日志当用户档案 |

## 5. 模块化单体候选

### 5.1 为什么作为首选候选

- 首期业务边界和供应商都仍需 PoC，模块化单体更容易保持一致事务、审计和快速调整；
- 用户、运营、GIS、知识、资产和 AI 之间有大量发布版本依赖，过早分布式化会放大同步和回滚成本；
- 单景区早期容量没有支持微服务复杂度的证据；
- 以明确模块 API、事件契约和数据所有权保持未来可拆分性，不以“同一进程”换取跨域随意读表。

### 5.2 领域模块及所有权

| 模块 | 拥有的数据/规则 | 对外能力 |
|---|---|---|
| Identity & Consent | 账号、角色、同意、撤回、会话 | 身份、角色、同意状态，不输出敏感凭证 |
| Scenic Catalog | 景区、体验范围、POI、入口、设施、别名 | 只返回达到目标发布级别的版本 |
| GIS & Routing | 内部节点/边、封闭、路径版本、公共路线引用 | 计算内部路线、拼接已核验入口、解释路线来源 |
| Operations Status | 开放、活动、设施、应急、有效期 | 只返回有效且已发布状态；过期即不可声称当前 |
| Knowledge & Narration | 证据、事实声明、讲解稿、音频、审核 | 有来源检索、引用、内容版本和撤回 |
| Travelogue Intake | 来源授权声明、最小原文、提取候选、原文跨度 | 生成待确认候选，不生成路线事实 |
| Itinerary & Visit | 用户确认点、路线引用、导览会话、打卡 | 保存/执行/恢复旅程；不默认保存原始连续轨迹 |
| Share | 私有或不可枚举链接、撤销与到期 | 输出结构化用户行程，不复制无权第三方全文/媒体 |
| Asset & Rights | 资产、许可、授权、衍生、发布 manifest | 仅向产品暴露可用且未撤权版本 |
| AI Orchestration | 风险分级、工具白名单、提示/模型版本、校验 | 结构化、带引证回答、明确拒答和降级 |
| Audit & Quality | 发布、访问、工具调用、纠错、评测摘要 | 不可篡改审计、质量与成本观测 |

## 6. 地图双层架构

### 6.1 公共道路层

- 责任：从公共道路、公交/停车候选到经核验景区入口的路线；
- 来源：被选定地图供应商的在线服务；
- 存储：仅保存合同允许的请求引用、供应商路线 ID、时间、坐标系和摘要；不得默认复制路线几何、瓦片或 POI 到自有数据库；
- 限制：供应商路线不证明景区内部门禁、台阶、封闭、无障碍或安全。

### 6.2 景区内部网络层

- 责任：经授权和现场核验的入口、步道、节点、设施、单向、封闭、无障碍候选与应急替代；
- 来源：景区管理方、合规采集主体、现场复核；
- 发布：草稿、现场核验、景区批准、发布、暂停/过期分级；
- 路由：只允许使用已发布且在有效期内的节点/边；临时封闭优先于历史路线。

### 6.3 连接不变量

1. 两层只能在已核验的 entrance 节点连接；
2. POI 代表点、建筑中心和入口必须是不同类型；
3. 原始坐标、原始坐标系、来源、采集时间永不被转换值覆盖；
4. WGS84、GCJ-02、BD-09 在存储和 API 中显式声明；
5. 无可用连接时返回不可验证，而不是直线连接或由 LLM 补路；
6. 主题图层失败时回退标准地图，同时保留路线、位置和任务状态。

## 7. 受控 AI 编排

### 7.1 编排原则

- 一个可观测的编排器管理意图识别、风险分类、结构化提取、检索、工具调用、输出校验和拒答；
- 活跃工具保持少量、只读、白名单；工具参数必须经过 schema、范围、租户和坐标系校验；
- 检索资料与游客输入始终是数据，不能成为系统指令；
- 模型输出永远是候选，只有确定性服务或人工审核能改变发布事实、路线或状态；
- 支付、公开发布、共享精确位置等有副作用能力首期不存在。

### 7.2 首期只读工具候选

| 工具能力 | 权威来源 | 失败策略 |
|---|---|---|
| 检索已发布知识 | Knowledge & Narration | 无证据即拒答 |
| POI 候选消歧 | Scenic Catalog + 地图适配器 | 展示多候选让用户确认 |
| 计算公共步行路线 | 地图适配器 | 不复用过期结果；展示官方入口/现场标识 |
| 计算内部路线 | GIS & Routing | 封闭或无路径时拒绝并引导人工 |
| 查询当前官方状态 | Operations Status | 显示无法核验和官方渠道 |
| 获取讲解资产 | Knowledge & Narration + Asset & Rights | 语音不可用则文字 |

## 8. 关键业务数据流

### 8.1 游记转行程

1. 客户端取得用户处理授权并提交最小必要文本或链接信息；
2. Travelogue Intake 隔离保存来源信息和处理状态；
3. AI 编排器提取地点、时间、偏好、约束、原文跨度和未决项；
4. Scenic Catalog/地图适配器返回限定景区的 POI 候选；
5. 客户端要求用户确认地点、入口、交通方式和敏感约束；
6. GIS & Routing 只以已确认点和有效网络计算路线；
7. Itinerary 保存确认结果、数据版本和路线引用；
8. 分享时只输出用户自己的结构化行程与允许的短引用/链接。

### 8.2 现场导览

1. 客户端加载行程、发布版地图/内部网络摘要、讲解 manifest 与有效状态；
2. 定位在端侧做精度、滞回、驻留、顺序和冷却判定；
3. 客户端上报最小事件：讲解点、粗粒度时间、触发方式、精度级别；不默认上传连续轨迹；
4. Narration 返回已发布文字/音频；用户能暂停、重播、看字幕；
5. 定位、音频或网络失败时分别转为手动到点、文字和已授权离线内容；
6. 打卡记录与精确轨迹分离。

### 8.3 内容发布

1. 来源/资产进入草稿并绑定许可；
2. 编辑形成单一可核验声明或讲解稿；
3. 事实、文化/宗教、权利和现场审核按风险执行；
4. 生成不可变发布版本和 manifest；
5. 索引、缓存和客户端只消费该发布版本；
6. 过期、撤回或投诉触发下架，索引和缓存同步失效，审计保留。

## 9. 多景区预留而不提前建设 SaaS

### 9.1 必须从首期保留

- 每个领域对象携带 scenic_area_id；
- API 从已认证上下文解析景区，不信任模型或任意请求体切换；
- 唯一约束、缓存键、对象存储路径、检索过滤和审计均包含景区；
- 地图供应商、坐标策略、内容政策、品牌主题和运营时区通过景区配置表达；
- 不允许跨景区检索知识、路由、资产、状态或用户运营数据。

### 9.2 首期不建设

- 景区自助开通、计费、套餐、白标域名、跨景区运营大盘；
- 多景区内容市场、自动迁移或复杂租户管理员体系；
- 独立租户数据库集群。

首期可用单库逻辑隔离候选，但必须以自动化隔离测试证明无越权；达到监管、合同或规模阈值后再评估 schema/数据库/集群级隔离。

## 10. 非功能目标候选

以下是 Gate 2 需确认、PoC 需测量的候选门槛，不是当前生产承诺：

| 维度 | 候选目标 |
|---|---|
| 可用性 | 核心浏览与文字导览月度 99.9%；第三方地图/AI 故障有明确降级 |
| 性能 | 良好 4G 下首个可操作地图/列表 P75 不高于 3 秒；AI 先返回处理状态，完整回答 P95 目标由 PoC 校准 |
| 弱网 | 自有已授权核心文字、讲解 manifest、行程和内部节点摘要可恢复；不缓存无权地图数据 |
| 安全 | 高权限 MFA、最小权限、敏感操作审计、密钥不进客户端/日志/文档 |
| 隐私 | 默认不上传连续精确轨迹；位置、语音、游记分别告知、同意、撤回和删除 |
| 可追溯 | 每条事实、路线、状态、媒体和 AI 回答可定位版本、来源、审核与有效期 |
| 可运维 | 状态过期、工具失败、配额异常、引用错配、发布/撤回失败有告警 |
| 无障碍 | 不依赖声音/颜色/动效完成核心任务；手动到点、文字和标准地图可用 |

## 11. 故障与降级矩阵

| 故障 | 系统行为 | 明确禁止 |
|---|---|---|
| 地图底图失败 | 展示已授权内部示意、节点顺序、入口说明和刷新入口 | 抓取或缓存未授权瓦片 |
| 定位被拒/漂移 | 手动选点/到点，显示精度与现场标识优先 | 假装已到达或上传更多位置补偿 |
| 公共路线失败 | 显示经核验入口与人工服务渠道 | 用直线或模型生成路线 |
| 内部网络过期/封闭 | 禁止路线并展示现场人员/替代状态 | 沿用旧路线 |
| AI/RAG 失败 | 直接展示审核内容或“暂无已核验资料” | 用模型记忆补全 |
| 实时状态源失败 | 标注失败时间和无法核验 | 显示过期状态为当前 |
| 音频/TTS 失败 | 字幕/文字、重试或已授权缓存音频 | 静默失败或自动换未经审核声音 |
| 权利撤回 | 下架资产和衍生版本，缓存/索引失效 | 继续展示或只删原件不删衍生物 |

## 12. Gate 2 架构决策清单

| 决策 | 当前建议 | 决定前证据 |
|---|---|---|
| 服务端形态 | 模块化单体候选 | 领域边界评审、容量模型、运维人力 |
| 首发客户端 | H5/小程序同契约 PoC 后决定 | 前后台定位、语音、弱网、审核、用户触达实测 |
| 地图 | 境内厂商 + 自有内部网络优先比较 | 同批点位、授权、审图、数据地域、成本、SLA |
| 事务/空间数据 | 支持事务与空间能力的关系库候选 | 几何、路由、版本、备份、国内托管对比 |
| AI | 单编排 + 可替换模型/RAG 适配器 | 中文文化、引用、工具、数据地域、成本评测 |
| 语音 | 审核预录/预生成优先 | 专名、噪声、权利、弱网和更新成本 |
| 多景区隔离 | 首期逻辑隔离、单景区启用 | 越权测试、未来合同/监管阈值 |

任何结论若引入长期费用、新供应商、跨境数据或改变核心路线，均需用户单独确认。
