# 六祖云游 MVP 与版本边界

状态：`GATE_2_APPROVED_BASELINE`  
版本：`Blueprint V0.1`  
基准日：2026-08-14（Asia/Shanghai）  
门禁：Gate 1 与 Gate 2 已通过；开工前六项准备度验收尚未通过，Implementation 仍锁定。

## 0. 核心定案

用户已批准的完整价值 MVP 是：

> 导入有权处理的游记或自然语言需求 → 提取地点、时间与约束并保留原文证据 → POI 消歧并由用户确认 → 用真实公共/内部网络计算路线 → 用户编辑并重新校验 → 前台/手动到点讲解 → 轻量打卡 → 保存并私有/链接分享。

为降低风险，执行时内部拆成两个切片：

1. **S1 现场可信切片：** 到达、正确入口、标准二维地图、真实路径、设施/状态、有来源讲解、异常与保存；
2. **S2 差异化切片：** 游记/需求结构化、原文证据、POI 消歧、用户确认、行程调整/重验、地图执行、打卡、私有/链接分享。

S1 可以先做 PoC；但 **S1 单独不等于 MVP**。完整 MVP 必须把 S1 与 S2 在同一可信数据和状态体系中贯通。

## 1. 版本名词与完成定义

| 名称 | 目的 | 必须包含 | 不能宣称 |
|---|---|---|---|
| 蓝图 | 定义产品、数据、技术、设计、测试与依赖 | 本阶段全部可审核文档、未决事项和 Gate 2 审核包 | 已开发、已上线、可真实导航 |
| 现场可信 PoC | 证明入口、路网、状态、内容与端侧降级可成立 | S1 的代表路径、失败/降级场景、现场实走和可核验数据 | 完整价值 MVP、全景区覆盖、公开生产能力 |
| 差异化 PoC | 证明游记/需求能安全转成待确认、可校验行程 | S2 从输入到 `READY/BLOCKED` 的代表样本和黄金集 | 已能处理任意网页/图片、所有地点或真实大规模使用 |
| 集成 MVP | 验证完整产品闭环 | S1 + S2 + 必要 B 端运营/审核/隐私/审计支撑 | 全镇、多景区、完整商业或社区生态 |
| 受控现场试点 | 在授权范围和受控人群中检验 MVP | 正式首发边界、真实数据、审核内容、预案、现场支持与监测 | 面向公众稳定服务或大客流承诺 |

## 2. 首发服务对象

### 2.1 第一优先用户

自驾或高铁到达、希望在有限时间内完成国恩寺及相邻核心区体验的独立游客/家庭。该选择源自 Gate 1 决策，但全年客群结构仍待普通工作日、周末与高峰的现场研究确认。

### 2.2 必须同时覆盖的使用条件

- 六祖文化/礼佛目的，要求克制、静音、事实类型分层；
- 家庭、长者、行动较慢、婴儿车等任务约束；
- 定位拒绝、低精度、弱网、音频不可用和切后台；
- 自驾与高铁/接驳两种到达方式；
- 普通日与高峰/临时封闭的不同状态。

“覆盖”表示流程不得排除这些用户，并不表示未现场核验的路线已经可无障碍通行。物理可达性未知时必须明确未知。

### 2.3 支撑用户

景区运营/游客中心、寺院与宗教事务相关人员、文保/非遗/地方史审核者、GIS/现场采集人员、交通/安全/应急责任人、隐私/法务/资产审核和审计管理员是 MVP 必需支撑角色。没有他们的数据与审核闭环，游客端不能宣称“可信”或“实时”。

专业导游/机构内容生产在数据对象上预留，但不在 MVP 开放外部自助发布、公开推荐或售卖。

## 3. 地理与内容边界

### 3.1 首发地理候选

首发只覆盖管理方最终确认的核心文化与服务区。当前候选：

- 游客服务中心；
- 国恩寺；
- 龙潭湖；
- 已核实开放的龙山步道片段。

这些名称来自 Discovery，并非自动纳入名单。每一对象必须通过“正式边界/管理主体 → 入口 → 现场路径 → 状态责任 → 文化/声音/拍摄规则 → 数据/素材权利”的发布链后，才可成为 MVP 可执行点。

### 3.2 扩展候选

| 层级 | 候选 | MVP 中允许的表现 | 禁止表现 |
|---|---|---|---|
| 扩展文化点 | 六祖故居、藏佛坑、惠能广场等 | 在输入中识别为范围外/待核验候选；可存愿望清单 | 自动加入核心区步行路线、声称连续可达或同一管理区 |
| 跨点/两天一夜 | 禅域小镇、温泉、民宿/酒店、香荔农旅 | 后续场景研究和数据结构预留 | 进入首发执行路线、实时库存/价格、功效或商业推荐 |
| 镇域/多景区 | 全镇乡村、多景区实例 | 通用对象模型预留 `scenic_area` 等边界 | 建设全镇导航或多景区 SaaS 后台 |

### 3.3 内容边界

MVP 只发布已经完成来源、事实类型、许可、审核者、版本、适用点、有效期和公开范围登记的内容。以下不得自动成为正式讲解：

- 平台评论、普通游记或营销文案；
- 许可不明的图片、视频、音频、字体、地图和图标；
- 历史、宗教、传说之间未分层的混合稿；
- 来源冲突却被 AI 合并成唯一答案的陈述；
- 未经寺院/文保确认的国恩寺声音、拍摄、位置触发或游戏化内容。

## 4. MVP Must / Should / Could / Won't

### 4.1 Must：缺一即不构成完整 MVP

#### A. S1 现场可信

- 清楚区分核心区与扩展点，支持自驾/高铁到达分支；
- 经核验入口级目的地，公共道路与内部网络仅在入口衔接；
- 标准二维地图与主题皮肤切换，空间、状态与进度不变；
- 经发布的内部路径、设施和开放/封闭状态；
- 定位精度可见、前台导览、暂停/恢复/结束与手动到点；
- 有来源/类型/审核/版本的文字讲解，以及满足许可的审核音频或明确文字降级；
- AI 无证据拒答、冲突并列，路线/开放/安全事实只读工具约束；
- 弱网、定位拒绝、低精度、地图/音频/AI 故障和后台暂停的清楚降级；
- 紧急/人工渠道；
- 私有保存。

#### B. S2 差异化

- 直接自然语言需求和粘贴有权文本；
- 地点、时间、顺序与约束的原文证据，明确/推断标记；
- 多候选 POI 消歧、范围标签和用户确认；
- 入口/路网/状态/约束可执行性校验，`READY/BLOCKED` 状态；
- 行程增删、排序、停留/约束调整，任何影响执行的修改重新校验；
- `READY` 行程无损进入现场导览；
- 用户确认式轻打卡；
- 默认私有、字段预览、可撤销/到期链接分享；
- 用户可删除输入/行程/分享，并有联动说明。

#### C. MVP 支撑

- 运营状态的来源、责任人、有效期、审核、过期降级、撤回与紧急发布；
- 文化命题/讲解的来源、类型、许可、多专业审核、版本与撤回；
- GIS 边界、入口、路网、设施的坐标系、来源、现场核验、发布和封闭；
- 最小角色权限和职责分离；
- 黄金集、发布前回归、零容忍门禁、反馈与审计；
- 定位、语音、游记和分享的分别告知、最小化和删除；
- 所有对外动态状态与生成内容的来源/时间/适用标识。

### 4.2 Should：提高首发可用性，可在受控试点前按证据排序

- 短/深讲解切换和知识卡收藏；
- 系统字号、高对比、路线列表、字幕、减少动态和单手操作的完整体验；
- 自驾/高铁入口信息的清楚比较与返程提示；
- 新旧路线差异解释；
- 已准备的必要文字/音频与安全卡弱网使用（取决于载体与数据许可）；
- 运营逾期提醒、反馈处理状态和发布影响预览；
- 经过法务/权利确认后的“禅小荔”知识助手呈现。
- 用户主动开启的**前台关键路线语音提示**：只播报确定性 RoutePlan 的下一方向/节点、距离、预计时间和到达信息；随时可静音，并始终保留等价文字。

### 4.3 Could：通过 PoC 与资源评审后才进入首发候选

- 单次按住说话 ASR；
- 低风险追问的实时 TTS；
- 主题皮肤的少量“香荔旅行手账”行前/行后元素；
- 经过现场与文化审核的少量非敏感数字印章；
- 满足地图许可和载体能力的有限必要内容预取；
- 粤语或第二语言的试点内容。
- 连续逐向转弯语音与自动重算；只有地图/载体、定位、弱网、场所声音规则和安全 PoC 通过后才进入首发候选，且不能由 LLM 生成路线。

Could 不得占用 Must 的入口、路线、状态、内容审核、隐私和降级资源；未通过 PoC 就不进入首发。

### 4.4 Won't：本 MVP 明确不做

- 全 3D、AR 寻宝、完整剧情/游戏、东方数字禅境；
- 国恩寺核心区游戏化、积分/排行榜和强打卡；
- 全镇全域连续导航、多景区 SaaS、自助景区接入；
- 公开社区、公开推荐流、导游路线售卖；
- 支付、商城、直播、广告和复杂商业推荐；
- 任意外部链接抓全文/媒体；
- H5 锁屏/后台持续导航保证、持续监听麦克风；
- 多 Agent、AI 自主发布/支付/预订/共享位置；
- 没有官方数据源的实时停车、客流、开放、安全或无障碍保证。

## 5. 内部验证顺序

顺序表示风险关闭关系，不是实施授权或固定日历。

### 验证 0：数据与责任可进入 PoC

**目标：** 确认 PoC 不使用假事实冒充真实产品。

必须准备：

- 明确标注的测试范围和代表入口/路线；
- 可用于 PoC 的来源、坐标系、现场轨迹和许可；
- 至少一组已审核文化命题/讲解；
- 模拟状态与真实状态严格区分；
- 测试人员、现场许可和安全预案；
- 不记录密钥值，接口只记录能力和环境要求。

退出：没有入口中心点混用、路线断裂/坐标系混乱、未授权素材或未审内容进入真实测试。

### 验证 1：S1 现场可信 PoC

**验证问题：** 游客能否在前台和手动降级下，到正确入口、沿真实路线、理解状态与文化，并在异常时安全退出？

代表场景：

- 自驾与高铁/接驳各一条到达分支；
- 标准/主题地图切换；
- 正常位置、低精度、拒绝定位和弱网；
- 正常路段、临时关闭、不可达；
- 普通讲解点与宗教/文保克制点；
- 长者/行动慢/婴儿车场景的“已知 + 未知”表达；
- 保存与删除。

退出门槛：PRD 的路线、文化、隐私、宗教空间零容忍缺陷为 0，且手动/文字/人工降级能完成所有 P0 任务。只通过这一验证，项目状态仍是“现场可信 PoC”。

### 验证 2：S2 差异化 PoC

**验证问题：** 有权内容能否被转成带证据、可消歧、可确认和可阻塞的行程，而不是一段看似合理的生成文本？

黄金样本必须覆盖：

- 规范地点、别名、错别字、同名多点和地址冲突；
- 范围外扩展点、无入口、不可达、状态过期和路段封闭；
- 明确时间与推断时间、冲突顺序和缺少交通方式；
- 长者/行动约束与可达性未知；
- 恶意提示注入、无权/敏感内容、无结果和工具失败；
- 编辑后重新校验、阻塞解释和删除。

退出门槛：所有执行节点来自用户确认，所有关键提取可回指证据，严重歧义误选和路线事实错误为 0。

### 验证 3：集成闭环 MVP

**验证问题：** S2 的 `READY` 行程能否在 S1 现场无信息丢失地执行，并完成打卡、保存和有限分享？

必须贯通：

`输入 → 提取 → 消歧 → 约束 → 校验 → 编辑/重验 → 现场会话 → 到点/讲解 → 打卡 → 私有保存 → 链接分享/撤销`

同时贯通 B 端：

`GIS/内容/状态发布或撤回 → 行程有效性变化 → 游客端/保存/分享同步提示`

退出门槛：PRD KPI 与验收场景达到 Gate 2 后确定的试点阈值；运营人员能维护代表状态和内容；严重撤回不同步、未授权公开或过期状态误导为 0。

### 验证 4：受控现场试点

**进入条件：** 首发正式边界、运营责任、内容/路网、隐私/法务、应急与现场支持已闭合；开工和测试另获授权。

覆盖普通工作日、普通周末和经批准的高峰/异常复盘；避免用单个春节样本外推全年。试点只面向明确范围与人数，设置现场人工接管、问题上报、暂停和下架门槛。

## 6. 发布级 Definition of Done

以下条件需同时满足；“页面做完”或“接口能返回”不等于 Done。

### 6.1 产品完整性

- PRD 所有 Must 有对应流程、页面/状态、数据对象、权限、接口契约、测试和责任人；
- S1 与 S2 完整贯通，不能用模拟页面替代真实数据/状态链；
- 入口、路线、讲解、保存与分享的异常分支可恢复或安全退出；
- 状态、版本、撤回和删除在游客/B 端一致。

### 6.2 真实世界与 GIS

- 首发边界、入口、节点、路径和设施有正式来源、坐标系、现场核验、发布权和版本；
- 公共与内部网络只在核验入口连接；
- 每条路线完成正/反向实走与高风险场景评估；
- 坡度、台阶、无障碍、弱网和危险点未知时不作肯定声明；
- 临时封闭能阻塞路线并同步正在执行的会话。

### 6.3 内容与宗教/文保

- 每个可核验陈述有支持来源、事实类型、核验者、版本和有效期；
- 国恩寺内容、声音、拍摄、触发和 IP 使用获得相应书面规则；
- 史实、宗教传统、地方传说、解释和营销分层；
- 文稿、字幕、真人/合成音频权利与生成标识闭合；
- 撤回/过期内容从检索、讲解、缓存和分享视图同步失效。

### 6.4 AI 与路线

- 单编排、只读白名单和结果校验；AI 不创造坐标、入口、路线、开放或安全事实；
- 提取字段有原文证据，歧义由用户确认；
- 无证据正确拒答、冲突并列、工具失败不回退模型记忆；
- 黄金集覆盖无答案、攻击、过期、歧义、坐标系和越权；
- 路线事实、文化来源和未授权副作用零容忍缺陷为 0。

### 6.5 体验与无障碍

- 户外日光、高对比、大字/系统字号、单手、屏幕阅读和减少动态通过 P0 流程测试；
- 地图、颜色、音频、动画或 IP 均有文字/标准图标/路线列表等价替代；
- 定位、网络、地图、音频和后台故障不伪装正常；
- 宗教空间少打扰，用户可暂停、跳过、关闭、静音；
- 不用数字 UI 无障碍冒充物理路线无障碍。

### 6.6 隐私、安全与运营

- 定位、麦克风、游记和分享分别告知、按需授权、可撤回/删除；
- 连续原始轨迹和常开麦克风默认不采集；
- 分享默认私有、字段最小化、链接可撤销且撤回真实生效；
- 角色最小权限、发布职责分离、密钥不进日志/文档、关键操作可审计；
- 运营、紧急、纠错、撤回和事故响应有责任人、SLA、演练与下架能力；
- 生成式 AI、拟人化、个人信息、版权、地图和宗教/文保要求取得上线时书面评估。

## 7. 零容忍缺陷

出现任一项即阻止对应 PoC/试点/发布；不能用“低概率”或“体验很好”豁免：

1. 把 POI 中心点当入口、直线当道路、穿越未发布/封闭区或坐标系错配；
2. 编造开放、票价、交通、客流、天气、应急、无障碍或安全状态；
3. 伪造文化来源、把传说当史实、引用不支持陈述；
4. 未经允许在宗教/文保敏感区自动播放、游戏化或诱导拍摄；
5. 未经用户确认执行公开发布、位置共享、预订、支付等有副作用行为；
6. 泄露密钥、精确轨迹、原始语音、游记、行动约束或他人私有内容；
7. 已撤回/过期的路线、状态或内容仍以现行事实展示；
8. 分享链接撤销后仍可访问，或私有内容进入公共搜索/推荐；
9. 定位/网络/工具失败时界面仍宣称正常实时导航或自动到点；
10. 用户无法关闭定位/音频/AI、撤销分享或发起删除。

## 8. 验收样本矩阵

每个代表路线/内容样本至少交叉覆盖下列条件，不能只测理想路径：

| 维度 | 样本 |
|---|---|
| 到达 | 自驾、高铁/接驳、到达方式不确定 |
| 同行 | 单人、家庭/儿童、长者/行动慢、婴儿车/轮椅需求（不预设可达） |
| 地点 | 规范名、别名、错别字、同名、多候选、范围外、无入口 |
| 路线 | 正常、不可达、临时封闭、状态过期、修改后重验、偏离 |
| 定位 | 正常、低精度、拒绝、撤回权限、前后台切换 |
| 网络/服务 | 正常、弱网、断网、地图失败、AI/RAG 失败、音频失败 |
| 内容 | 史实、宗教传统、地方传说、冲突、无答案、过期/撤回、提示注入 |
| 讲解 | 文字、审核音频、静音敏感点、暂停/跳过/重播、相邻点防串播 |
| 保存/分享 | 私有、预览、链接、撤销/到期、官方内容撤回、用户删除 |
| 运营 | 普通状态、紧急关闭、冲突、过期、退回、撤回、审计 |
| 无障碍 | 日光、高对比、系统大字、屏幕阅读、单手、无音频、减少动态 |

具体测试数量、阈值和责任人由测试蓝图给出；所有严重安全/事实/隐私缺陷仍为 0 容忍。

## 9. 依赖分级

### D0：阻塞 Implementation 开工

- 产品、UI、系统架构、数据模型、API、测试与环境蓝图获得 Gate 2 确认；
- 首发正式边界和代表 PoC 路线的合法可用数据；
- 既有系统/接口/账号/产权盘点；
- 地图、AI、语音、云等候选 PoC 范围、预算和授权决定；
- Logo/IP 和外部素材在开发/公开使用上的权利决定；
- 数据、隐私、生成标识、网络安全和宗教/文保责任方案；
- 开工前需求、API、资源、设计、数据库和环境六项验收通过。

### D1：阻塞现场可信 PoC

- 至少一组代表入口、内部路径、设施和状态责任；
- 至少一组经文化/宗教/文保审核的讲解；
- 现场采集与测试许可、安全预案和测试人员；
- 定位/地图/音频在候选载体上的实机能力；
- 模拟状态与真实状态隔离方案。

### D2：阻塞受控现场试点/公开首发

- 首发全部范围、入口、路线、设施、无障碍声明和弱网情况闭合；
- 开放、停车、接驳、封闭、活动和应急的责任数据源与 SLA；
- 寺院/文保对讲解、声音、拍摄、位置和 IP 的书面规则；
- 所有生产素材许可、生产供应商合同和数据处理评估；
- 运营值守、应急演练、客服/纠错、暂停/下架与事故处置；
- 现场试点 KPI 达标且零容忍问题关闭。

## 10. 版本变更控制

任何新增、提前或删减功能必须形成变更记录，至少回答：

1. 是否增强核心体验，而非只增加展示效果？
2. 是否直接服务首发游客或可信运营？
3. 是否支持未来复用且不提前建设多景区平台？
4. 增加了哪些数据、版权、宗教、隐私、安全、供应商、预算和长期维护成本？
5. 不做它是否会使完整价值 MVP 无法闭环？

### 10.1 允许在第二阶段内自主细化

- 不改变功能价值的术语、流程、验收、错误状态和文档一致性修订；
- 增补安全、无障碍、隐私、测试和数据来源要求；
- 在不锁供应商的前提下拆分 PoC 与比较维度。

### 10.2 必须提交用户确认

- 将 S2 移出 MVP、把 S1 单独命名为完整 MVP；
- 首发扩展至六祖故居/藏佛坑/惠能广场、跨点两天一夜、全镇或多景区；
- 新增 3D、AR、完整游戏/社区、商城/支付/直播/广告；
- 开启公开 UGC、路线售卖、持续监听、长期轨迹或多 Agent；
- 锁定核心载体/地图/模型/数据库/云供应商；
- 新增长期付费服务或显著运营成本；
- 改变产品定位、目标用户、商业模式或文化/隐私原则。

## 11. Gate 2 已批准的产品决定

| 决定 | 已批准基线 | 准备度阶段仍需证据 |
|---|---|---|
| 完整价值 MVP | 保留 S1 + S2 + 支撑能力 | 正式范围、资源与责任签字 |
| 验证顺序 | 先 S1 高风险现场 PoC，再 S2，再集成；顺序不等于删减 S2 | PoC 输入、停止阈值与单独执行授权 |
| 首发边界 | 管理方确认的核心文化与服务区 | 正式名单、入口、路网、设施和状态责任 |
| 分享 | 匿名草案本地保存；跨设备/分享时登录；默认 7 天、可撤回、只读、不复制为草稿 | 最长时限、同步/冲突、删除/审计和法务签字 |
| AI | 受控单编排、只读工具、无证据拒答 | 模型、RAG、地域、条款、质量和成本证据 |
| 语音/位置 | 审核讲解、前台/手动到点；关键前台语音为 Should，持续导航为条件性 PoC | 场所、权利、真机、弱网和定位证据 |
| 视觉 | 现场 A“岭南禅径” + 少量 B“香荔旅行手账”，C 延后 | Logo/IP 权利未闭合时继续使用中性占位 |
| 商业 | 只验证体验、运营、游记转路线和数字资产；首期无支付、广告、商城或售卖 | 无；未来扩张重新走人工确认 |

Gate 2 已确认仍不等于立即编码：必须完成开工前六项准备度验收，并再次收到明确开发授权。
