# 运营运行手册

本手册定义未来受控发布时的操作顺序，不代表生产接收器、值班人员、数据库或恢复能力已经配置。

## 正常发布

1. 由相互独立的审核人与发布人确认景区数据、权利、内容、路网/运营快照、现场证据和发布理由。
2. 2026-08-15 已在干净隔离候选完成生产构建、TypeScript、lint（零错误）、Node 测试（318/318）和全量 Playwright（34/34，约 5.5 分钟）。任何后续候选变更都必须在隔离环境重新执行并归档；这不是生产部署证据。
3. 只使用数据库名含 `test`/`ci` 且除 `spatial_ref_sys` 外无公共表的一次性、非生产真 PostGIS 环境运行 `../scripts/verify-postgis.mjs`；必须显式提供 `DATABASE_TEST_URL`、`ALLOW_DATABASE_INTEGRATION_TESTS=1` 与 `DATABASE_TEST_CONFIRM_DISPOSABLE=1`。验证器会自动发现全部迁移，执行全量前进/补偿/重放，再用虚构数据验证 N6–N12 多角色分离、动态观测完整快照发布与 N9 最终快照插入故障的事务零残留；运行后数据库不可复用。当前本机没有 PostgreSQL/Docker，`npm run verify:release` 在连接前停止，未触及任何真实数据库。
4. 执行 `npm run p0:release-evidence` 与 `npm run verify:release`。当前 P0 账本为 12 条规则、38 个场景、49 项非通过及 9 项开放外部阻断，结论 `NO_GO`。任何 `PARTIAL`、`MISSING`、`BROKEN`、`MOCK`、`UNVERIFIED` 或外部阻断均必须非零退出。
5. 部署后以 `../src/app/api/readiness/route.ts` 判断地图/数据核心是否可用；`/api/health` 只用于 liveness，不能代替 readiness。

## Preview 与移动候选

- 当前 Vercel Preview 的基础地址继续受 Vercel Authentication 保护。受控分享入口是可撤销的测试访问凭证，不得写入仓库、日志、工单或公开群；撤销后必须重新打包 Android 候选。
- Android debug APK 只能侧载测试，且必须显式注入已核验 HTTPS 地址；遗漏 `webAppUrl` 时构建按设计失败。它不是 release APK/AAB，没有真机、商店或生产签名证据。
- iPhone 当前只允许通过 Safari 打开受控 HTTPS 候选并“添加到主屏幕”。没有 macOS/Xcode、Apple Developer 签名和真机矩阵时不得声称已有 IPA。
- 回滚候选部署或撤销分享入口时，应同时通知测试人员停止使用旧 APK；旧安装包不具备自动迁移到新访问凭证的能力。

## 封路与紧急通知

1. `OPERATIONS_EMERGENCY` 只能在 `/admin/route-operations` 选择当前正式快照中安全状态与运营状态均为 `OPEN` 的边，填写来源、原因证据、事件类型、说明、开始和强制失效时间，并确认旧路线会立即停止。不得上传候选几何或用口头推测替代证据。
2. `CLOSED/RESTRICTED` 事件按开始时间立即成为旧快照的失败关闭条件。游客端停止旧指令；只有另行发布了完整的新运营快照后才可确定性重算。没有新快照或无安全替代路线时转现场标识和人工求助。
3. 不同 OIDC subject 的 `RELEASE_ADMIN` 应按既定 SLA 检查事件、来源和现场证据，然后确认或撤回。确认维持阻断至到期；撤回只移除这一事件，不得写成或口头解释为“道路已经开放”。需要延长时应创建具有新证据和有效期的新事件，而不是修改追加历史。
4. 每次提交或复核使用唯一幂等键和精确 revision；网络超时后以相同请求重试，先核对审计回执，不得反复创建相同事件。动作记录不可更新/删除，`admin_audit_events` 与 `route_closure_event_actions` 应共同进入事后审计。
5. 当前代码门要求真数据库、`ROUTE_OPERATIONS_ENABLED=1`、可信边缘签名身份、OIDC/MFA 和租户角色。未配置真实角色、官方事件源、责任人、复核 SLA、通知渠道和现场演练时，不得把该流程称为已运行。

## 替代运营快照

1. 只有所有仍有效管制以及客流/天气观测均已完成独立复核后，`OPERATIONS_EMERGENCY` 才可在同一工作台生成替代候选。准备请求只填写当前 snapshot revision、HTTPS 依据和说明，不得上传路网、坐标、几何、边状态或权重。
2. 服务端会把所有已确认、未撤回、未到期事件，以及每条路段最新的已确认有效观测，完整编入全边运营状态。计划稍后开始的确认事件也从新快照发布时起保守阻断。候选剩余有效期不足十分钟、快照不完整、边映射漂移或存在待复核事件/观测时停止，不得人工绕过。
3. 候选生成后，由另一 OIDC subject 的 `RELEASE_ADMIN` 核对基础/目标快照、运营 version、事件/观测数、影响边数、到期时间和 SHA-256，并提供独立 HTTPS 发布证据。准备人不得切换角色自发布。
4. 发布会在同一事务中撤下旧快照、标记旧运营 version 为 `SUPERSEDED` 并发布新快照。发布人必须同时确认：在线导航需要按版本重算，所有绑定旧 snapshot/version 的离线包失效并须重新审核、签名和分发。
5. 网络超时使用相同幂等键重试并先查审计回执；事件集合、观测集合、基础快照或候选摘要发生任何漂移都要重新准备，不能修补不可变候选。过期候选保留审计但不占用当前队列。
6. 管制或替代快照到期只让正式导航失败关闭，不能解释为道路开放。恢复开放必须有新的责任来源、完整全边状态、独立发布和现场流程。
7. 该能力还要求 `ROUTE_OPERATIONAL_RELEASE_ENABLED=1`。真 PostGIS 迁移/补偿/并发与故障注入、官方事件源、真实多人、值班轮转、离线撤回再签和现场演练未完成时不得启用生产发布。

## 客流与天气动态观测

1. `OPERATIONS_EDITOR` 在 `/admin/route-operations` 只能选择当前正式快照中状态为 `OPEN` 的路段，填写客流 `LOW/MODERATE/HIGH`、天气 `NONE/RAIN/HEAT/WIND/MULTIPLE`、1–3 倍耗时、10–1000 字现场说明、观测/失效时间和 HTTPS 一手依据。最长有效期六小时；倍率为 1 时只允许 `LOW + NONE`。
2. 每条路段同时只保留一项待复核观测。提交只进入不可变复核队列，不直接改变运营版本、游客 ETA 或路线；不得把帖子数量、主观印象或未校准单一传感器当作事实来源。
3. 不同 OIDC subject 的 `OPERATIONS_REVIEWER` 独立核对路段、时间、采集方法、现场说明、倍率和证据后确认或拒绝。复核时快照/路网已变化、观测已到期或提交人与复核人相同时停止。
4. 已确认观测只有被下一次完整运营快照精确绑定 ID 与 SHA-256、并由另一 `RELEASE_ADMIN` 发布后才影响游客路线；发布前的新观测、待复核观测、到期或哈希漂移均要求重新准备。游客端逐段披露已应用倍率、客流和天气。
5. 当前能力还要求 `ROUTE_OPERATIONAL_OBSERVATIONS_ENABLED=1`。正式启用前必须定义管理方责任源、采样/校准方法、交叉核验、异常值规则、最长更新间隔、到期轮转、值班/复核 SLA、日志留存和现场真机演练；当前没有六祖镇正式观测数据。

## GIS 正式化与发布

1. 只有不可变提交已由不同 `GIS_REVIEWER` 审核为 `APPROVED_FOR_FORMALIZATION`，第二位 GIS 人员才可在 `/admin/gis-formalization` 准备正式化计划。提交人、原审核人、准备人不得合并。
2. 逐条核对路径的公共/内部层、绘制方向、来源、许可、坐标精度与有效期。入口必须精确落在两层顶点，POI/设施必须精确落在内部顶点；不允许为“通过”而吸附、移动或补造坐标。
3. `RELEASE_ADMIN` 发布前核对计划 SHA-256、节点/边/POI 数量、静态有效期和短期运营来源。全边初始 `OPEN` 是一次明确运营确认；不能由草稿、事件到期或“没有收到封路”推断。
4. 若旧路网有未撤回管制或待发布运营快照，停止正式化发布。先按事件/运营工作流闭环，不能用新全开放版本绕过阻断。
5. 成功发布会原子撤下旧快照、旧版本和绑定旧快照的在线离线包。立即核对游客快照版本、readiness、审计事件和离线包队列；另行完成新包审核、签名与传播。离线设备未联网前不能保证已经收到撤回。
6. 网络超时使用同一幂等键重试并先查审计回执。任何来源、提交摘要、计划摘要或有效期漂移都必须重新准备，不得修改不可变候选。
7. 生产启用还需 `GIS_FORMALIZATION_RELEASE_ENABLED=1`、真 PostGIS、真实 OIDC/MFA/角色、官方 GIS/许可、现场双向复走与管理签字；当前代码证据不能代替这些材料。

## 自动重路由与失败处置

1. 连续三个可靠样本确认偏航，或 15 秒/页面恢复复核发现正式路网或运营版本变化时，游客端必须先停止旧逐向指令并记录 `REROUTE_REQUIRED`；不得先显示猜测性方向。
2. 仅使用设备内存中 10 秒内、精度不高于 35 米的定位样本保守匹配当前正式节点。“最近节点距离 + 定位精度”超过 80 米、样本陈旧或低精度时停止；路线请求不得包含坐标、精度、时间戳、轨迹、朝向或几何。
3. 重新获取并完整验证当前线上快照；断网时只可使用仍有效、验签且资产哈希完整的已安装离线包。沿用游客原路线策略、优化项和显式交通/无台阶偏好，以匹配节点和原目的节点调用同一确定性图算法。
4. 替代路线必须具有不同指纹，并精确匹配景区、起点、目的地、路网版本、运营版本、策略、优化项和偏好。版本变化还要通过运营重算判定；全部通过后才能记录 `REROUTED`、切换地图/指令并恢复导航。
5. 无新鲜定位、无正式节点、目的地已移除/已到达、快照过期或不完整、离线包失效、无可达路线、版本/指纹不匹配时继续保持停止，并明确引导游客查看现场标识或联系工作人员。不得回退旧路线、候选 GIS 或未经批准的外部路线提供方。
6. 生产启用前必须完成代表性机型的多路径/林下/建筑遮挡、节点稀疏、连续偏航、弱网/断网、正式封路版本切换、无替代路线与反复重算抖动测试，并由 GIS、安全和景区运营共同签字。

## 逐向口令与定位置信度核验

1. GIS 正式化时，每个真实路口、分岔、出入口、换乘点和需要游客作决定的位置都必须成为正式道路边界；仅用于贴合弯曲道路形状的中间坐标不得拆成导航决策点。
2. 发布前逐边核对 `distanceMeters` 与几何量测、方向、道路名称/类型和现场标识。运行时剩余距离等于当前边剩余量加后续边总量；不能用错误的整条折线比例掩盖单边量测问题。
3. 双向现场复走逐条比对转向种类、距路口距离、方向箭头与可见标识。弯道内部不得出现左转/右转口令；真实分岔不得因边界缺失而只提示继续直行。
4. 定位精度圈显示浏览器报告的半径：蓝色表示可靠，金色表示等待或低精度，红色表示指令已停止；非可靠状态隐藏旧方向箭头。该圆不代表真实误差概率，测试人员必须同时记录设备、浏览器、环境和现场偏差。
5. 覆盖 200%/400% 缩放、非颜色文本状态、读屏说明、强光和色觉差异。颜色或精度圈不能成为唯一安全信息，顶部文字状态和现场标识必须始终可用。
6. 在正式路网中单独标记交叉、重叠、平行、回头和空间靠近但路线进度相距很远的路段；以双向、停留、折返和横穿交叉口脚本验证当前位置不会从早段跳到远端或终点。首次落在完全重叠几何时应从最早安全进度起算。
7. 远端分支疑似匹配前两次必须暂停方向并显示复核状态，第三次才进入 `REROUTE_REQUIRED`；随后按“自动重路由与失败处置”核对新快照、新指纹和无 GPS 上传。单次跳变不得直接宣布偏航或到达。
8. 在走廊内先正向建立最远进度，再安全折返。扣除精度后反退超过 20 米且连续三个可靠样本时应显示“已确认反向行走”和掉头提示，不应产生新的路线 API 请求；回到最远进度 8 米内后恢复正常。分别覆盖站立不动、GPS 漂移、真实掉头、陡坡、交通段和路线自身交叠。
9. 对每条现场路线核对灰色已走线与蓝色剩余线在真实当前位置相接，路口、边界、折返点和终点不存在缝隙、跳段或提前清空；未取得可靠匹配时必须整条蓝色，不得凭数字进度比例切线。
10. 索道/观光车进入前、乘行中、离开后分别核对虚线只覆盖剩余服务段。正式 traversal 与路线几何段数不一致时，进度敏感交通虚线应隐藏而不是把已乘坐服务显示为待乘。
11. 暂停、页面恢复和手动恢复时保留最后确认的灰/蓝分界，但清空连续偏航、到达、分支跳变和反向证据；恢复后首个新鲜可靠样本再更新。覆盖低端机 GPU、200%/400% 缩放、旋转、强光、色觉差异和读屏说明。
12. 可靠定位开始后确认地图进入“自动跟随当前位置”；拖动、缩放或旋转后必须显示“手动浏览地图”，后续连续定位不得抢回视野。只有游客显式选择“回到当前位置”才能恢复跟随。
13. “查看剩余路线”必须只使用当前未完成几何；总览期间 GPS 可继续更新路线进度和当前位置，但不得改变相机模式。到达后总览只定位终点，不重新显示已走路线。
14. 低精度、定位不可用、反向警告、偏航停止或运营版本停止时，相机不得因旧点自动移动；回中控件在没有可靠位置时保持禁用。真机覆盖多点触控、系统缩放、设备旋转、前后台、Safari/Chrome/微信内置浏览器、减少动态和低端 GPU。
15. 收到 `visibilitychange(hidden)`、`pagehide` 或 `freeze` 任一信号时，连续定位必须停止；重复信号不得产生重复会话暂停。最近重算定位样本必须清除，最后确认路线只可作为暂停画面，不得继续推进。
16. 收到 `visibilitychange(visible)`、`pageshow` 或 `resume` 后先读取完整正式快照；复核期间定位和恢复按钮保持关闭。版本变化进入确定性重算，正式状态不可用则继续停止。
17. 版本一致也不得自动恢复导航。游客显式确认后才重新启动前台 watch，并等待符合新鲜度/精度门限的新样本。真机演练必须覆盖锁屏、BFCache、系统回收、权限撤回、长时间后台、弱网和语音/会话联动。
18. 前台关键语音默认关闭，只能由游客在本次页面会话中显式开启。每次播报必须来自当前路线指纹、正式道路边与结构化 maneuver；同一正式边只在进入更近距离分档并满足冷却后重播，曲线造型点不得制造新语音决策。
19. 全局静音、页面后台/冻结、手动暂停、定位不可靠、偏航、反向、运营版本变化、退出和到达必须先取消正在播放的旧指令；安全提示使用固定有界文案，不朗读任意错误文本、坐标、路线指纹或日志。回前台显式恢复后，只有新的可靠定位才能重新播报。
20. 浏览器语音不可用或播放失败时只降级为文字、地图、方向和现场标识，不阻断定位或路线状态机。真机演练记录设备/浏览器/声音、系统静音、耳机/蓝牙、来电抢占、静音区、噪声、中文发音与读屏并行表现；浏览器自动化不能替代这份记录。

## 索道与观光车发布

1. 交通候选路径必须只有两个端点，并登记官方服务名称、上车准备、预期等候、乘坐时长和可追溯 HTTPS 班次依据；折线形状可包含中间坐标，但不能拆成会重复计费等待时间的多条交通边。
2. 发布人与 GIS 审核人分别核对上下客点、运行方向、换乘步行衔接、无障碍状态和证据有效期。票价、末班时间、即时排队或临时停运没有专门字段与责任来源时不得写入游客提示。
3. 静态服务资料不能替代当前运营状态。交通边必须在短期全边运营快照中明确为 `OPEN` 才能规划；`CLOSED`、`RESTRICTED`、未知、缺边或过期均停止使用，不以预计等待时间推断运行中。
4. 游客端默认不采用索道/观光车；只有游客分别显式选择后才可规划。无台阶选择还要求交通边正式标为 `VERIFIED_ACCESSIBLE` 且无台阶，并完成上下客点、车厢/轿厢和衔接路线现场核验。
5. 当前没有任何六祖镇正式交通线路数据。第十五号迁移、编辑器和算法只证明软件约束存在，不构成交通服务、时刻表、票务或现场安全发布。

## 事故与恢复

- GIS、运营状态过期、数据库不可用或发布快照不完整：核心 readiness 为 `BLOCKED`，停止正式内部导航。
- AI/语音不可用：最多降级为已审核文字或关闭，绝不能影响安全判断。
- 发生泄露疑虑：撤销分享/会话、清理过时缓存、按授权轮换秘密（绝不在工单记录值）、保全脱敏审计并通知责任人。
- 恢复只能从已演练的备份/PITR 执行；恢复后复核迁移、租户隔离、封路状态、权限和 readiness，才可考虑恢复服务。

`../src/lib/server/readiness.ts` 与 `../src/lib/server/observability.ts` 仅是可替换接口。生产告警接收器、值班表、RTO/RPO、备份合同、恢复记录和真实回执均属于未关闭外部阻断。
