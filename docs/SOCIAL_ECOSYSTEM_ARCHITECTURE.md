# 地图社交生态系统架构与融合设计

更新时间：2026-08-16

## 1. 已形成的产品闭环

第一阶段以“地点社区”为唯一社交入口：游客从地图选择一个地点，进入该地点社区，查看分层标注的游客内容，主动读取一次设备位置后发布动态或完成打卡，再在个人旅行档案中查看足迹。

当前交付分为两条明确隔离的运行链：

| 能力 | 本机原型 | 服务端公开链 |
|---|---|---|
| 地点社区与演示内容 | 可体验，演示内容永久标注 | 只读取同租户、绑定正式 POI 的 `PUBLISHED + VERIFIED` 社区和 `APPROVED` 公开内容 |
| 动态、图片、点赞、评论 | 本机保存，可刷新恢复 | 真实账号、真库、对象存储、审核开关齐备后启用 |
| GPS 绑定 | 每次发布/打卡单次授权，距地点超过 5 公里拒绝 | 服务端再次用 PostGIS `ST_DWithin` 校验 |
| 旅行打卡与足迹 | 默认私密、本机保存 | 精确点私有；公开资料只返回服务端降精度点 |
| 实时游客数与热度 | 不提供，不用演示数字伪装实时数据 | 第二阶段接入有责任主体的数据源后再开放 |

## 2. 前端信息架构

### 路由

- `/community`：默认地点社区、跨社区动态流、本机发布入口。
- `/community/[placeId]`：每个候选地点的独立社区 URL。
- `/profile/[handle]`：旅行数据、个人足迹与最近打卡。
- `/map`：新增“地点社区”任务页签和“地点社区入口”图层；开启后地图标记直接进入对应社区。
- `/account`：继续承担真实游客账号的登录与跨设备身份入口。

### 主要交互流

1. 地图进入社区：`地图 → 地点社区图层 → 地点标记 → /community/[placeId]`。
2. 发布动态：`选择社区 → 写内容/类型/可见范围 → 选择并压缩图片 → 单次 GPS 授权 → 距离校验 → 本机发布或服务端待审`。
3. 旅行打卡：`选择社区 → 日期/备注/同行人/照片 → 单次 GPS 授权 → 默认私密保存 → 旅行档案足迹`。
4. 内容互动：`点赞 → 幂等反应记录`；`评论 → 字数校验 → 待审核 → 公开展示`。
5. 个人主页：只统计可见范围允许的数据；公开主页不返回精确打卡点或私密旅行轨迹。

### 界面状态

所有社交页面都包含加载、空、错误和权限状态。定位拒绝、距离过远、图片处理失败与本机存储不足分别反馈；主要按钮有按压反馈，动效遵守 `prefers-reduced-motion`。

## 3. 前后端分层

```text
Next.js 页面 / 客户端交互叶组件
  ├─ 本机原型存储（localStorage，图片先缩放并转 WebP）
  └─ /api/v1/social/*
       ├─ 同源检查、限长 JSON、身份会话、幂等键
       ├─ 社交领域校验（类型、可见范围、GPS、文本、标签）
       ├─ PostgreSQL/PostGIS 事务与租户隔离
       └─ 对象存储/CDN 与审核流水线（配置后开放）
```

服务端社交链需要同时满足：

- `DATABASE_URL` 已配置；
- `SOCIAL_API_ENABLED=1` 显式启用；
- 已应用 `004_social_ecosystem.sql`；
- 已应用 `009_formal_place_communities.sql`，地点社区已与同景区正式 POI 一对一绑定；
- 社区、正式 POI 与所属 publication 均已通过审核、进入公开状态且仍在有效期；
- 图片对象存储、CDN、病毒扫描、元数据清理和内容审核已配置；
- 公开写入使用真实游客会话、同源请求和幂等键。

未满足时 API 返回 `SOCIAL_CAPABILITY_DISABLED`，不会把本机数据假装成服务端成功。

## 4. API 契约

| 方法 | 路径 | 用途 | 公开边界 |
|---|---|---|---|
| `GET` | `/api/v1/social/communities/:placeId/posts?scenicAreaId=...` | 游标分页地点动态和 24 小时摘要 | 同景区正式 POI 绑定；只返回公开且审核通过的内容；位置为社区中心点；不接收游客 GPS |
| `POST` | `/api/v1/social/communities/:placeId/posts` | 创建带 GPS 的动态 | 登录、同源、幂等；创建后为 `PENDING` |
| `POST` | `/api/v1/social/posts/:id/reaction` | 点赞/收藏/去过/想去/加入计划 | 复合唯一键保证幂等 |
| `POST` | `/api/v1/social/posts/:id/comments` | 评论 | 登录、限 500 字、进入待审核 |
| `POST` | `/api/v1/social/check-ins` | 保存旅行打卡 | 私密精确点与降精度公开点分列保存 |
| `GET` | `/api/v1/social/profiles/:handle` | 公开旅行档案 | 只统计公开内容，不返回精确坐标 |
| `GET` | `/api/v1/social/uploads/policy` | 媒体能力与限制探测 | 未配置对象存储时明确返回关闭 |

后续新增上传时采用“服务端申请上传会话 → 浏览器直传对象存储 → 服务端回调校验 SHA-256/大小/MIME → 清理元数据和生成响应式 WebP → 内容审核 → CDN 发布”的链路，应用服务器不代理大文件。

## 5. 数据库重设计

### 第一阶段核心表

- `social_profiles`：账号的公开旅行档案，与 `visitor_accounts` 一一绑定。
- `place_communities`：地点社区，强制带景区租户、地点 ID、WGS84 点、来源、核验状态和采集时间；第九号迁移为公开社区增加正式 POI UUID + canonical code 一对一外键，旧候选不自动回填。
- `social_posts`：动态正文、类型、可见范围、作者、社区、精确 GPS、精度、采集时间和审核状态。
- `social_media_assets` / `social_post_media`：对象存储键、CDN URL、文件摘要、处理状态、权利声明与动态排序。
- `social_comments` / `social_reactions` / `social_post_tags`：评论、互动和标签。
- `travel_check_ins`：旅行打卡；精确位置和公开降精度位置分列。
- `travel_records`：后续连续旅行记录；私密与公开降精度轨迹分列。

### 第二、三阶段预留表

- 关系：`social_follows`、`friend_relations`。
- 群组：`travel_groups`、`travel_group_members`。
- 消息：`conversations`、`conversation_members`、`social_messages`、`social_notifications`。
- 官方与治理：`official_accounts`、`social_reports`。

### 关键约束

- 所有社交写入都带 `scenic_area_id`，避免跨景区越权。
- 正式社区读、发布与打卡同时核验同租户社区、`FIELD_VERIFIED` POI 和 `PUBLISHED` publication 的当前有效期。
- 动态必须同时绑定 `community_id` 和 WGS84 位置；数据库再次校验与社区距离。
- 公开 Feed 只命中 `PUBLIC + APPROVED + 未删除` 的部分索引。
- 原始上传令牌、会话令牌、密钥和对象存储凭据均不入库。
- 用户 GPS 只证明“发布者提供了这个位置”，不能升级为官方地点、开放状态或安全信息。

## 6. 图片、视频与性能

当前原型在浏览器端把图片最长边缩至 1440 像素并转 WebP；单张原图上限 12MB，单条动态最多 4 张，本机只保留最近 30 条动态。Feed 图片懒加载并使用稳定宽高比。

公开版本使用客户端直传对象存储与 CDN 分发，应用数据库只保存资产引用；原图私有保存，公开使用响应式派生图。MIME、魔数、大小、像素、病毒、敏感内容和 EXIF 元数据全部在发布前校验。Feed 使用 `(scenic_area_id, community_id, created_at, id)` 键集游标分页；地图社交点按视口聚合，热区只使用满足最小匿名人数的数据窗口。

## 7. 权限、隐私与内容治理

- `PUBLIC`：审核通过后可出现在地点社区和公开档案。
- `FRIENDS`：第二阶段好友关系上线前只允许本机预览，不做服务端公开读取。
- `PRIVATE`：只对本人读取；打卡精确位置不得出现在公开 API。
- 删除、导出、同意撤回需扩展既有隐私数据权利事务，把社交表纳入级联清理与导出清单。
- 官方标识只由 `official_accounts.verification_state=VERIFIED` 且在有效期内产生。
- 人流、热度、实时开放和临时关闭不能由帖子数量直接推导；没有责任主体与数据时显示“无法核验”。

## 8. 分阶段交付

第一阶段当前实现：地点社区、动态发布、图片压缩与上传抽象、GPS 绑定、点赞评论、旅行主页、打卡记录、地图社交入口、数据库迁移与服务端 API 契约。

第二阶段：好友/关注、私聊、兴趣群、官方账号、消息中心、举报审核后台、权威实时状态接入。上线前需补齐未成年人保护、内容审核 SLA、位置隐私和运营责任人。

第三阶段：AI 旅行助手、智能组队、个性化推荐与跨景区/全球社区。AI 只使用用户授权的数据；推荐需要可解释退出开关，组队默认不暴露精确位置。

## 9. 当前发布结论

本次实现是可运行的第一阶段本机原型与服务端工程基础，不构成生产社交平台放行。真实公开 UGC、跨设备图片、好友可见内容、实时游客与官方社区仍需真库、对象存储、审核治理、隐私评估、运营责任和现场/官方数据共同闭环。
