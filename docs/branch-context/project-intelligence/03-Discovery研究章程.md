# Discovery 研究章程

## 成功标准

Discovery 完成时，项目应当能够用证据回答：

- 六祖镇的真实范围、主要文化与旅游节点是什么？
- 游客实际如何到达、游览、停留、求助、拍照、休息和离开？
- 哪些体验值得被 AI 增强，哪些不能靠 AI 猜测？
- 第一版最小闭环是什么，哪些功能必须延后？
- 高德、Mapbox、OpenStreetMap 等方案在中国境内真实导航、定制视觉、成本和合规上的差异是什么？
- AI 导游应如何依赖审核知识库、位置与地图服务，怎样降低幻觉？
- 品牌 Logo 与“禅小荔”IP 应如何影响视觉方向？
- 开发所需地图、POI、文化、图片、视频、音频、3D、动效、API 等资产准备到什么程度？

## 研究范围

### 1. 真实地理与 POI

- 行政边界、景区/文旅节点边界
- 山体、河流、道路与步行可达性
- 出入口、停车场、游客中心、卫生间、餐饮、休息点、无障碍与应急设施
- POI 坐标、开放信息、推荐停留时间、讲解价值和核验状态

### 2. 六祖文化与地方文化

- 六祖惠能、南宗禅及相关历史脉络
- 国恩寺、六祖故里旅游度假区及相邻文化节点
- 新兴县建筑、民俗、节庆、物产与地方故事
- 事实、宗教传统、地方传说和营销表达必须分层标注

### 3. 用户与行为

- 普通游客、文化游客、家庭游客、年轻游客、银发/无障碍游客
- 专业导游/内容创作者、景区管理者和运营人员
- 行前、行中、行后任务、痛点、风险和成功指标

### 4. 竞品

- 国内外智慧景区、AI 导游、游记转行程、位置触发讲解、数字文旅平台
- 只分析可验证能力与体验，不根据营销文案推断内部实现

### 5. GIS 与地图技术

- 中国境内地图合规、坐标系、底图、POI、步行路径、定位、路径规划
- 主题皮肤、矢量覆盖层、离线/弱网、性能、SDK 限制、成本与数据授权

### 6. AI 导游

- 游记解析、结构化行程、RAG、位置触发、讲解、追问、推荐、语音
- 来源约束、审核流程、拒答/不确定性、实时信息调用和成本控制

### 7. 视觉与资产

- 建筑、山水、植物、人文、色彩、纹样、地图、UI、动效与 IP
- 视觉候选方向：禅意水墨、国风动漫旅行手账、东方数字禅境
- 初始组合建议只能作为待确认假设，不能直接定案

## 来源层级

| 等级 | 来源 | 允许用途 |
|---|---|---|
| A | 政府、景区官方、开放平台官方文档、法规/标准原文 | 事实与技术能力依据 |
| B | 权威机构、学术资料、企业官方案例与公告 | 补充与交叉验证 |
| C | 携程、马蜂窝、小红书、抖音等游客内容 | 行为、痛点、视觉和传播信号 |
| D | 聚合、转载、搜索摘要 | 发现线索，不能单独作为结论 |

## 证据规则

- 每个关键事实记录 URL、页面标题、发布主体、访问日期和可信级别。
- 对可能变化的信息注明“截至 2026-08-14”及复核频率。
- 坐标至少用两个独立地图/数据来源交叉核验，正式上线前仍需现场或景区方确认。
- 游客评论以主题和模式总结，不把单个评论推广为普遍事实。
- 推断必须明确标为“推断”；方案必须明确标为“建议”；未核验项必须进入缺口清单。

## 资源获取规则

- 优先保存原始公开资料、结构化数据、许可清晰的可用素材。
- 对许可不明的图片/视频只保存来源链接、缩略研究描述和建议拍摄清单。
- 不绕过付费墙、登录限制、技术保护或平台条款批量下载。
- 每个可用资源都进入资产登记表并记录许可、作者/主体、用途和本地路径。

## 第一版 MVP 待验证假设

候选闭环：选择六祖镇 → 生成/选择路线 → 真实二维地图执行 → 到点讲解 → 轻量打卡 → 保存/分享路线或游记。

候选延后项：全 3D 地图、AR、完整游戏系统、完整社交社区、商城、直播、多景区运营平台。

上述均须经 Discovery 证据和用户 Gate 1 审核确认。
