# 开工前准备度验收计划

状态：`IN_PROGRESS_0_OF_6_GREEN`  
版本：V1.0  
启动日：2026-08-14（Asia/Shanghai）  
授权依据：[Gate 2 批准记录](../handoffs/Gate2批准记录.md)

## 1. 目标与边界

本阶段只回答一个问题：项目是否已经具备开始 Implementation 的真实条件。

当前继续禁止：编码、创建应用、建库/迁移、安装开发依赖、部署、采购、付费调用。外发联系、现场采集和需要代码的 PoC 也必须单独授权。

六项全部为 `GREEN` 仍不会自动开工；还必须由用户再次明确授权进入 Implementation。

## 2. 状态规则

| 状态 | 含义 |
|---|---|
| `RED` | 存在 B0 阻塞、必要证据不存在或相关行动未授权 |
| `AMBER` | 蓝图或部分证据存在，但外部事实、责任、权利、条款或验证未闭合 |
| `GREEN` | 必要证据完整、版本有效、责任人签字、回退清楚且无未解决 B0 |

任何项目从 `RED/AMBER` 转为 `GREEN` 必须引用证据 ID、文件位置、版本/日期、责任人和签字。口头推测、营销页、已有 API key、免费额度或“后续补”不能作为转绿证据。

## 3. 六项验收标准

### R-REQ 需求准备度

必须同时具备：

- Gate 2 已批准的 PRD、流程、功能地图和 MVP 边界；
- 36 项需求与测试、数据、API、Sprint 和依赖的追溯；
- 正式首发范围、入口、路线、设施、动态状态和内容责任；
- 所有 Must 的异常、降级、验收和外部依赖已关闭或由获批范围缩减处理；
- KPI/任务阈值、账户/分享规则、运营/审核角色完成版本锁定。

### R-API API 准备度

必须同时具备：

- 自有与外部接口目录、schema、版本、鉴权、坐标系、错误、超时、配额和降级；
- 景区既有系统和动态状态源的正式接口/人工流程；
- 地图、AI、语音、存储等候选的书面条款、数据处理、缓存/再分发和 SLA；
- 可用样例/沙箱或获批准的等价验证证据；
- 每个核心契约有负责人和测试映射。

### R-RES 资源准备度

必须同时具备：

- 发布级边界、入口、内部路网、设施、无障碍、安全与状态数据；
- 命题级文化资料、寺院/文保/非遗审核与现场互动规则；
- Logo/IP、图片、音频、字体、图标和地图资产的权利与生产源文件；
- 现场许可、参与人员、设备、测试用户和运营主备责任；
- 获批准的预算与缺失资源替代方案。

### R-DES 设计准备度

必须同时具备：

- 已批准 UI、页面、地图和状态/组件规范；
- 关键流程的可验证原型或等价交互证据；
- 真实内容/资产规格、标准地图回退、弱网/权限/空/错误状态；
- 目标设备、强光、系统字号、读屏、减少动态、静音和无障碍任务验证；
- 品牌、IP、文化和场所规则签字。

### R-DAT 数据库/数据准备度

必须同时具备：

- 已批准逻辑模型、数据字典、ID/隔离、来源、权利、版本和有效期规则；
- 首发生产数据达到发布门槛并可追溯；
- 保留、删除、撤回、匿名/账户、7 日分享、审计和敏感数据规则获法务/隐私确认；
- 候选数据库/存储的地域、备份、恢复、迁移、退出、容量和成本证据；
- 迁移/回滚方案获评审，但本阶段不创建数据库。

### R-ENV 开发环境准备度

必须同时具备：

- 经用户批准的开发/测试环境方案、供应商和预算；
- 账号、角色、最小权限、秘密、环境隔离、日志与数据分类；
- 备份/恢复、观测、成本告警、CI/CD 与回滚计划；
- 支持责任、事故升级、退出与清理流程；
- 用户在六项全绿后明确允许搭建环境和开发。

在当前“禁止安装、部署和采购”约束下，R-ENV 保持 `RED` 是预期状态，不得绕过。

## 4. 执行顺序

1. `R0 已完成`：记录 Gate 2 原话，同步十项批准决定与项目状态；
2. `R1 当前`：盘点本地已有证据，建立逐项缺口和责任台账；
3. `R2 待授权`：向景区、寺院/文保、既有 IT、品牌/法务和候选供应商索取书面资料；
4. `R3 待授权`：进行现场、真机或需要代码的受限 PoC；
5. `R4`：逐项复核证据，允许 `RED → AMBER → GREEN`，形成准备度验收报告；
6. `R5`：六项全绿后，请用户独立确认是否进入 Implementation。
