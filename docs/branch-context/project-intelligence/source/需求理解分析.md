# 需求理解分析（Discovery 基线）

状态：`DRAFT / 待调研验证`

基线来源：根目录 `原始需求.txt`，SHA-256 见《本地输入清单》。本文件是分析，不覆盖原文。

## 一句话定位

基于真实地图与真实景区数据，通过可替换文化视觉层、AI 行程结构化和景区内位置感知导览，让游记变成可以执行、导航、讲解和再分享的旅程。

## 三项核心能力

### 1. 真实地图 + 可定制文化皮肤

地理位置、道路、距离、设施、路线和时间必须可信；水墨、禅意、动漫、手绘、节庆和 IP 只改变表现，不改变空间关系。

### 2. 游记/导游日记 → 可执行行程

AI 提取景区、景点、顺序、时间、停留、交通、餐饮、理由和注意事项，生成可显示、执行、收藏、调整和动态更新的结构化路线。

### 3. 景区内部实时 AI 导览

位置、路线、下一站、设施与完成进度来自地图/定位能力；讲解来自审核知识库；AI 支持追问、推荐和动态调整。

## 用户价值假设

- 游客：少做攻略、少迷路、获得更深的文化理解和更有趣的打卡体验
- 专业导游/博主：将内容转化为可执行路线与情景式 AI 体验
- 景区：沉淀可治理、可复用的地理与文化数字资产

## 产品创新假设

- 真实空间与文化视觉皮肤分层
- 将游记从阅读内容变成可执行行程
- 行前规划、行中导航/讲解与行后分享闭环
- 基于位置主动触发讲解
- 真实地图与审核知识库约束 AI 幻觉

## 候选 MVP 闭环

选择六祖镇 → 选择/生成路线 → 在真实二维地图上执行 → 接近景点时获得可信讲解 → 轻量打卡 → 保存/分享路线或游记。

这只是 Discovery 待验证假设，不是已批准范围。

## 候选首期能力

- 六祖镇数字入口
- 真实二维地图与 POI/路线/服务点
- 主题化文化覆盖层或图标体系
- 基于偏好或游记的结构化路线
- 到点讲解与追问
- 轻量打卡、路线保存和分享

## 候选延后项

- 全 3D 数字孪生
- AR 导览
- 完整游戏与复杂剧情系统
- 完整社交社区
- 商城、直播、广告与复杂支付
- 多景区 SaaS 管理后台

## 关键待验证问题

1. “六祖镇”在产品中的正式体验边界是行政镇、六祖故里旅游度假区、国恩寺周边，还是多个文旅节点组合？
2. 哪些内部道路和设施数据可合法获得、缓存、修改和公开？
3. Web/H5 在景区弱网、后台定位、语音播报和持续导航方面能否满足真实使用，是否最终需要小程序或 App？
4. 游记结构化后，如何用真实路网、营业信息与可达性约束路线？
5. 讲解资料由谁审核，宗教史、地方传说与宣传表达如何分层？
6. Logo 与“禅小荔”是否拥有商用、改编和公开部署授权？
7. 第一版核心验证对象优先是游客体验、导游创作还是景区数字化合作？

## 目前不能当作决定的内容

- Next.js、React、FastAPI、PostgreSQL/PostGIS 等仅是历史对话中的候选建议
- 高德、Mapbox、Cesium 等尚未比较完成和经用户确认
- 70% 水墨、20% 动漫、10% 科技是视觉假设，不是已批准设计
- 0–3 个月 MVP 等时间表尚无资源估算支撑
