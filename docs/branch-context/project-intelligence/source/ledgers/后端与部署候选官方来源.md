# 后端与部署候选官方来源

> 状态：`RESEARCH_SNAPSHOT`  
> 核验日期：2026-08-15（Asia/Shanghai）  
> 用途：为真实账号、PostgreSQL/PostGIS、原子发布和跨设备分享选择可迁移的基础设施；本文不是采购批准，也不含密钥、报价承诺或生产配置。

## 当前结论

1. 数据层继续采用**供应商中立的 PostgreSQL + PostGIS 契约**。阿里云 RDS PostgreSQL 与腾讯云数据库 PostgreSQL 的官方文档均证明受支持版本可安装 PostGIS，因而无需为了当前预览锁死境外 BaaS。
2. 面向中国大陆真实游客的生产版，优先对阿里云/腾讯云境内地域做同口径 PoC、合规、SLA、备份、退出与成本评估；当前 Vercel 继续只承载可体验演示，不推定其满足大陆生产数据地域要求。
3. 若继续使用 Vercel 函数，必须显式选择靠近数据库的运行地域；官方文档显示 Node.js 函数默认运行在美国 `iad1`，而可选计算地域包括香港 `hkg1` 和新加坡 `sin1`。数据库与函数跨地域会增加延迟和数据跨境审查工作。
4. Supabase 当前官方可选亚太主区域包括新加坡、东京、首尔、孟买和悉尼等，未列中国大陆地域；它适合国际化 PoC 候选，不直接作为大陆生产默认方案。
5. 任何真实实例创建、付费套餐、DPA/合同确认、生产密钥注入与用户数据迁移仍须单独形成可核验记录。
