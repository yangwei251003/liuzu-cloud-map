# 三阶段执行与门禁协议

本协议来自用户引用的《AI景区开发规划》最后确认方案，是本项目的最高流程约束。

## 第一阶段：Discovery

角色：AI 数字文旅研究院 / AI 产品研究团队。

输入：

- 原始需求
- 阶段 1：角色与使命
- 阶段 2：真实世界、用户、竞品、视觉、技术和资源调研规则
- 阶段 3：六祖镇落地与 MVP 边界

目标：不是开发，而是理解使命、研究真实世界、建立完整产品认知体系。

必须交付：

1. 《六祖镇数字文旅深度调研报告》
2. 《用户需求与游客行为分析》
3. 《智慧旅游竞品分析》
4. 《GIS地图技术调研》
5. 《AI导游Agent方案研究》
6. 《视觉设计方向研究》
7. 《资源资产库规划》

明确禁止：建项目、写产品代码、创建数据库、启动 React/Next.js 开发。

完成后由用户审核产品方向、技术路线、视觉路线和 MVP 范围；必须收到明确确认才能进入第二阶段。

## 第二阶段：产品设计与技术架构

状态：`GATE_2_APPROVED`（用户于 2026-08-14 明确批准 Gate 1 与 Gate 2；第二阶段蓝图成为开工前准备度验收基线）。

角色：产品设计团队 + 技术架构团队。

输入：用户已确认的 Discovery 结论。

目标：生成完整开发蓝图。

预期交付：

- 产品：PRD、用户流程、功能地图、MVP规划
- 技术：系统架构、数据库设计、API设计、部署方案、安全方案
- 设计：UI规范、页面结构、地图皮肤设计
- 研发：版本路线图、Sprint计划、验收标准、测试方案

第二阶段交付获用户确认后，曾继续禁止编码、建库、安装产品依赖、采购或部署，并另行执行开工前准备度验收。此处记录的是历史门禁；当前状态以 [`00-项目状态.md`](00-项目状态.md) 为唯一事实源。

## 第三阶段：Implementation

状态：`AUTHORIZED / PROTOTYPE_GATE_PASSED`。用户已于 2026-08-14 依据 DEC-0005 明确授权进入原型 Implementation；生产门禁仍未通过，不能把候选 GIS、未审核内容或预览环境表述为正式上线成果。

进入条件：

1. 七份 Discovery 报告通过用户审核；
2. 开发文档体系完成并通过用户第二次确认；
3. 开工前验收通过：需求、API、资源、设计、数据库与开发环境均达到可开工状态。

执行时必须加载：

- 阶段 5：自主研发管理协议
- 阶段 6：AI 项目负责人决策权限协议
- 阶段 7：长期平台化与生态扩展协议
- 阶段 8：开工前项目准备度验收

## 确认的含义

只有用户明确表达“确认 Discovery 结论并进入第二阶段”或语义等价的指示，才算 Gate 1 通过。

只有用户明确表达“确认第二阶段开发蓝图并进入开工前准备度验收”或语义等价的指示，才算 Gate 2 通过。Gate 2 只批准蓝图方向，不自动允许开发；开工前六项准备度全部通过后，仍须用户再次明确允许进入 Implementation。

一般性的“继续”“优化一下”“再看看”不自动视为越级授权；应结合上下文判断并记录。
