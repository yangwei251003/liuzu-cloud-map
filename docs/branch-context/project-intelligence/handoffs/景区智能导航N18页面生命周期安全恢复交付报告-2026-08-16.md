# 景区智能导航 N18 页面生命周期安全恢复交付报告

日期：2026-08-16  
结论：软件闭环完成；生产仍为 `NO_GO`

## 1. 修复的问题

此前正式导航只监听 `visibilitychange`。常见切后台能够暂停，但移动 Safari、微信内置浏览器、BFCache 与系统冻结还可能通过 `pagehide/pageshow` 或 `freeze/resume` 改变页面生命周期。异步开始、运营复核或重算若刚好在后台完成，也存在把定位重新激活的竞态；后台前最近定位还可能在短时间返回时被重算复用。

## 2. 当前实现

- 新增 `FOREGROUND / BACKGROUND / VERIFYING / READY_TO_RESUME / STOPPED` 纯状态机。
- `visibilitychange(hidden)`、`pagehide` 与 `freeze` 去重处理；任何事件发现运行时仍为活动状态都会立即再次暂停，阻断异步激活竞态。
- 后台暂停停止 Geolocation watch，并清除只用于自动重算的最近可靠定位样本；最后确认路线匹配仅保留在内存，用于暂停画面，不推进距离或方向。
- `visibilitychange(visible)`、`pageshow` 与 `resume` 只启动一次恢复复核。系统重新读取完整正式快照；版本变化进入 N13 确定性重算，状态不可用则旧指令继续停止。
- 版本一致时仍保持 `PAUSED`，显示“确认恢复导航”。只有游客显式确认、页面仍在前台且再次通过运营复核后，才重新启动定位并等待新的可靠样本。
- 后台、复核中、待确认恢复和停止均有可见文字与读屏 live 状态；相关按钮在不安全阶段禁用。
- 页面生命周期、GPS 样本、事件顺序和后台时长不进入 API、CacheStorage、导航历史或日志。
