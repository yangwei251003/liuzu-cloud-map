## 3. 推荐蓝图摘要

### 3.1 产品与用户

- 首发优先服务自驾或高铁到达、希望在有限时间内完成核心文化体验的独立游客和家庭。
- 首发只覆盖管理方最终确认的核心文化与服务区；未确认的扩展点只能识别和保存愿望，不能生成可执行路线。
- 现场可信切片与差异化切片共同构成完整 MVP：前者验证真实空间可信，后者完成“游记/需求 → 证据化提取 → POI 消歧确认 → 真实路线 → 导览打卡 → 私有保存/分享”。
- 只完成现场地图和讲解时，只能称为 PoC，不能称为完整 MVP。

### 3.2 体验与视觉

- 现场以 A“岭南禅径”为主：清晰、克制、真实地理优先；行前与行后少量使用 B“香荔旅行手账”增加温度；C“东方数字禅境”延后。
- 游客端采用四项以内一级导航，AI 作为行程与现场任务中的上下文能力，不建立脱离任务的万能聊天入口。
- 户外体验基线包括 48×48 px 最小触控区、正文至少 16 px、WCAG AA 对比、系统字号、减少动态、静音、标准地图一键回退，以及位置/弱网/权限失败时的等价流程。
- Logo 与“禅小荔”权利或生产源文件未闭合时，只用中性占位，不把现有展示图当作可生产资产。

### 3.3 地图、AI 与技术

- 公共道路由合规地图能力提供，景区内部路线由经现场确认的自有网络数据提供；二者只能在核验入口连接。
- 模型只能做意图理解、结构化和有证据表达，不能生成权威坐标、道路几何、开放状态或安全决定。
- AI 首版采用受控单编排、只读白名单工具、审核 RAG、命题级来源与无证据拒答，不采用多 Agent 或带副作用的自主执行。
- 语音以审核过的预录/预生成为优先；首版 Must 是前台确定性的文字/地图方向、距离和 ETA，Should 是可静音的关键前台语音提示，持续逐向语音与自动重算仅在专项 PoC 后进入 Could；不承诺 H5 锁屏/后台持续导航，也不常开麦克风。
- 服务端以模块化单体和供应商适配器作为候选，空间关系数据库作为候选；全链路保留 `scenic_area_id` 逻辑隔离，但首期只启用一个景区，不提前建设 SaaS 控制台。

### 3.4 内容、发布与隐私

- 历史记录、宗教传统、地方传说、解释、营销、游客体验和实时状态必须分型展示，不由模型混为事实。
- 统一发布链为：编辑提交 → 适用的专业/权利审核 → 独立发布管理员原子发布；发布管理员不替代内容审核。紧急发布只允许预授权例外并需事后复核。
- 入口、路线、运营状态、文化内容、音频和资产都保留来源、审核、版本、有效期、权利与撤回联动。
- 默认不公开精确轨迹；游记原文、位置、语音、偏好和分享遵循最小必要、明确同意、可撤回与可删除。

### 3.5 交付顺序

1. 先完成正式数据、责任、权利、供应商条款和无代码证据准备；
2. 获得独立授权后，先验证现场可信 PoC；
3. 再验证游记/需求结构化与真实路线闭环；
4. 集成完整 MVP 后做真机、弱网、无障碍、隐私和运营演练；
5. 发布仍需独立审批，不由 Sprint 完成自动触发。

## 4. Gate 2 决策包

以下十项采用“推荐基线 + 保留证据门槛”的方式确认。批准推荐基线并不等于批准尚未验证的供应商、费用、正式数据或开发动作。

| Decision ID | 推荐决定 | 批准后锁定什么 | 仍留给准备度验收的事项 |
|---|---|---|---|
| G2-DEC-01 产品范围 | 确认 S1 现场可信 + S2 差异化闭环 + 必要运营/审核支撑共同构成 MVP；先验证 S1 不等于删除 S2 | 首版价值、Must/Won't、PoC/MVP 名称 | 正式首发边界、入口、路网和责任方签字 |
| G2-DEC-02 用户与载体 | 独立自驾/高铁游客与家庭优先；页面蓝图保持平台中立，以 H5/小程序同口径证据后决定 | 用户、户外/长者/家庭条件和四项导航 | 真机前台定位、弱网、音频、微信规则、维护与触达证据；不先锁载体 |
| G2-DEC-03 地图与路线 | 公共道路/内部路网分层，只在核验入口连接；高德是已配置候选但须与其他可行方案同口径比较 | 地理不变量、坐标/来源/版本责任和标准地图回退 | 正式 GIS、现场实走、审图/缓存/组合条款、SLA、报价和替代方案 |
| G2-DEC-04 AI 与语音 | 受控单编排 + 只读工具 + 审核 RAG + 无证据拒答；核心讲解预录/预生成优先；只把关键前台语音列为 Should | AI 权限、事实边界、语音范围和拒答原则 | 模型/检索/语音质量、专名、数据地域、DPA、权利、成本及是否启用 Could |
| G2-DEC-05 架构与数据 | 模块化单体、供应商适配器、空间关系库候选；全链路逻辑隔离但首期单景区 | 领域边界、可替换性、数据一级字段和不硬编码六祖镇 | 具体语言/框架、数据库/云、容量、迁移退出、备份和供应商决定 |
| G2-DEC-06 视觉与 IP | 现场 A 为主、行前/行后少量 B、C 延后；权利未齐时使用中性占位 | 视觉方向、无障碍与真实地图优先级 | Logo/IP 定稿、权属、商用/改编/发布授权和生产源文件 |
| G2-DEC-07 账户与分享 | 匿名浏览和手动建路线；匿名草案仅设备本地；跨设备保存或创建可撤销链接时再登录；链接默认 7 天、可提前撤回，首版不允许接收者复制为草稿 | 默认私有、最小登录、分享只读与版权边界 | 身份方案、同步冲突、到期后删除/审计、最长有效期和法律评审 |
| G2-DEC-08 商业与延后 | 首版不做支付、广告、商城、售卖、公共社区、排行、3D/AR、直播、多 Agent 或全域 SaaS | 防止功能膨胀和过早商业化 | 后续版本必须重新提交价值、成本、维护和风险评审 |
| G2-DEC-09 责任与质量 | 指定景区、寺院/文保、GIS、运营/应急、IT、法务/隐私、安全和品牌资产的主备责任；安全/事实/权利错误零容忍 | 职责分离、审核发布链和质量门禁 | 具名联系人、SLA、签字、黄金集、现场与运营演练 |
| G2-DEC-10 取证与费用权限 | 允许在后续准备度阶段收集公开/书面资料和同口径询价；外发联系、现场采集、需要代码的 PoC、付费调用和任何采购仍逐项单独授权 | 比较口径、费用与供应商不得暗中锁定 | 预算上限、审批人、联系人授权、PoC 执行范围和采购决定 |

若用户不接受某一推荐项，应直接引用对应 `Decision ID` 修改；未被修改的项目仍按推荐基线审阅。

## 5. 仍未闭合的硬阻塞

1. 经管理方确认的首发范围、入口、内部路网、设施、无障碍段和安全限制；
2. 国恩寺、文保/非遗和文化内容的命题级审核，以及拍摄、声音、定位触发和 IP 出现规则；

6. 载体、地图、AI、语音、云与数据库的书面条款、地域、隐私、SLA、费用和退出方案；
7. 隐私影响评估、地图/AI/内容合规、未成年人和敏感数据边界；

| 准备项 | 当前快照 | 下一步 |

| API | `RED` | 获取既有系统/动态源/候选服务的正式契约、条款和降级证据 |
| 资源 | `RED` | 取得正式 GIS、内容审核、权利、现场许可、人员与预算证据 |
| 设计 | `AMBER` | 结合真实资产、真机和现场条件完成验证；当前只保留蓝图 |

| 开发环境 | `RED` | 在最终开工授权前完成账号、权限、秘密、隔离、备份和成本方案；仍不搭建环境 |
