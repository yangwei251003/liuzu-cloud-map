# 景区智能导航 N12 动态运营观测交付报告

日期：2026-08-16（Asia/Shanghai）

## 交付结论

N12 已完成“证据化短期观测 → 独立复核 → 完整运营快照编译 → 独立原子发布 → 路线 ETA 消费与游客逐段披露”的软件闭环。实现没有插入、推测或发布任何六祖镇真实客流、天气、路线或开放事实。

当前仍是受控开发候选，生产结论保持 `NO_GO`。软件完成不能替代真 PostGIS、生产身份、正式采样责任、校准/代表性、更新 SLA、真机和现场演练。

## 已实现范围

1. 第十六号 PostgreSQL/PostGIS 迁移与受保护补偿：新增短期运营观测、追加动作审计、发布候选观测绑定、观测数量与不可变约束。
2. 新增 `OPERATIONS_EDITOR` 与 `OPERATIONS_REVIEWER`：编辑人与复核人 OIDC subject 必须分离；仍由独立 `RELEASE_ADMIN` 发布完整快照。
3. 严格观测合同：只允许当前正式快照中的开放边；客流为 `LOW/MODERATE/HIGH`，天气为 `NONE/RAIN/HEAT/WIND/MULTIPLE`，倍率 1–3，有效期最长六小时，说明和 HTTPS 一手来源必填。
4. 工作流保护：幂等写入、同边待审唯一、提交/复核追加审计、快照和路网 revision 复核、过期/自审/漂移/不完整输入失败关闭。
5. 完整快照发布：每边选择最新有效确认观测，与已确认管制事件共同覆盖编译全路网；候选精确保存观测 ID 和 SHA-256，发布前重新检查全集、待审状态、到期和哈希。
6. 管理与游客体验：`/admin/route-operations` 支持观测编辑和独立复核；正式路线逐段披露已采用的客流、天气与倍率，并明确计入 ETA。
7. 真库验证器扩展为 N6–N12：使用完全虚构的 `HIGH + RAIN × 1.8` 观测验证双人复核、独立发布、snapshot/version 递增、精确绑定、动作审计与不可变触发器。
