## 1. 本矩阵解决什么

Gate 2 和开工前准备度是两道不同的门：

1. **Gate 2——开发蓝图审核**：用户判断产品、设计、技术、研发、测试和依赖方案是否值得按该方向继续；
2. **开工前准备度验收**：在 Gate 2 通过后，用证据确认需求、API、资源、设计、数据库和开发环境六项是否真的可开工；
3. **Implementation 授权**：只有前两道门通过，且用户明确允许进入开发后才生效。

因此：蓝图文档“已写完”不等于 Gate 2 通过；Gate 2 通过也不等于外部数据/权利/接口/环境已就绪；任何一般性的“继续”不自动构成编码授权。

## 5. 六项开工前准备度矩阵

### 5.1 判定方法

每项采用：

- `RED`：有 B0 缺口或尚未授权，不能开工；
- `AMBER`：蓝图/候选已具备，仍需外部证据或决定；
- `GREEN`：证据齐全、责任人签字、版本锁定且仍在有效期；

只有六项全部 `GREEN`，并取得用户明确开发授权，才可能把 Implementation 解锁。

## 7. Gate 2 审核流程（执行中）

1. `COMPLETED`：完成全部第二阶段文档，文件状态统一为可审核；
2. `COMPLETED`：完成跨文档审计，统一范围、用户、术语、实体、API、状态、权限、验收、依赖、成本和延后项；
3. `COMPLETED`：检查本地链接、秘密泄露、非法媒体、越阶段实现和无证据事实；
4. `COMPLETED`：把用户决策压缩为 [Gate 2 审核包](Gate2审核包.md)，明确推荐、保留证据和不决定的后果；
5. `COMPLETED`：用户已批准 G2-DEC-01 至 G2-DEC-10，原始回复已写入批准记录与 DEC-0004；
6. `CURRENT`：执行六项开工前准备度取证；必要的外联、现场、代码 PoC、采购或环境行动仍逐项取得授权；
7. 六项全绿后提交开工前验收报告；
8. 只有用户明确允许开发，才更新状态并开始 Implementation。

## 8. 必须停止并询问用户的情况
