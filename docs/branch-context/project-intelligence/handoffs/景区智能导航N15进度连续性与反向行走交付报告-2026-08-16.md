# 景区智能导航 N15 进度连续性与反向行走交付报告

日期：2026-08-16  
结论：软件闭环完成；生产仍为 `NO_GO`

## 1. 修复的问题

逐向运行时此前把定位投影到整条路线的全局最近线段，并在等距时偏向更大的路线进度。回头线、交叉线、重叠线或相邻平行段可能让一个空间上合理的 GPS 点瞬间跳到路线远端，错误缩短剩余距离甚至误报接近终点。运行时也没有区分“仍在正式路线上但沿反方向行走”和“已经离开路线”。

## 2. 当前实现

- 每个可靠定位样本生成全部路线投影候选；首次完全重叠时选择最早安全进度。
- 已建立进度后，只接受路线进度变化不超过“设备实际移动 + 前一精度 + 当前精度 + 15 米缓冲”的候选；等距时优先与上一进度连续。
- 当空间最近候选位于不连续远端分支并明显优于连续候选时，前两次返回 `JUMP` 并停止方向，连续第三次进入 `OFF_ROUTE/REROUTE_REQUIRED`，沿用现有无 GPS 确定性重算。
- 远端分支样本已经通过新鲜度、精度和速度门，因此只更新设备内“最新可靠定位”供确认后的节点重匹配；旧路线进度保持不变，方向仍停止，样本不上传或持久化，避免从过时旧点重算。
- tracker 在设备内存保存当前进度、路线几何总长、最远已达进度和短时证据计数；这些字段不进入可序列化 runtime、API、导航历史、缓存或日志。
- 仍在路线走廊内、相对最远进度扣除当前精度后反退至少 20 米且连续三个样本时，导航显示 `WRONG_WAY` 和“在安全位置掉头”提示；回到最远进度 8 米内自动恢复。
- 反向行走保持原正式路线，不触发路线 API；真正偏航或连续远端分支歧义仍走 N13 的完整快照与新指纹重算。
