# 景区智能导航 N11 多模式交通交付报告

日期：2026-08-16（Asia/Shanghai）

## 交付结论

本轮把既有 `CABLEWAY`（索道）和 `SHUTTLE`（观光车）从普通道路标签升级为可审计、可失败关闭的景区交通段。软件已能在游客显式选择后规划步行与交通组合路线，并输出上车、乘坐、下车提示及分段 ETA；默认路线不会静默使用交通工具。

当前没有导入、回填或声明任何六祖镇真实索道/观光车线路。功能仍须官方线路、运营与现场证据后才能供游客使用，生产结论保持 `NO_GO`。

## 核心实现

- 候选 GIS：索道/观光车必须登记服务名称、上车准备、预期等候、乘坐时长和 HTTPS 班次依据；交通路径只允许两个端点。
- 正式化：交通 ETA 严格为三段时间之和，不按步行速度计算；发布计划与审核工作台持续展示服务证据。
- 路由：默认只允许四类步行边；索道/观光车分别显式选择。交通服务资料缺失、运营状态关闭/限制/未知/过期、方向或无障碍约束不满足时失败关闭。
- 导航：路线包含交通 traversal，运行时输出 `BOARD_*`、`RIDE_*`、`ALIGHT_*` 指令；剩余 ETA 按当前交通段与后续边计算，地图以独立虚线显示交通段。
- 数据库：`015_scenic_transport_routing.sql` 添加服务字段及交通/步行互斥约束，配套同名补偿脚本；迁移不写真实线路。
- 智能行程与离线：均复用同一路由引擎和游客显式交通选择，不产生另一套隐式规则。

## 自动化证据

- 秘密扫描、ESLint、TypeScript、全量 Node/契约测试 440/440、39 页面生产构建和 `verify:demo` 全部通过。
- 新增覆盖：默认步行、显式交通、缺服务失败关闭、交通 ETA、上车/乘坐指令、候选字段、正式化两端点、数据库迁移/补偿和浏览器请求体不默认携带交通模式。
- 当前生产构建在独立 3214 端口完成游客导航与 GIS 正式化专项 Playwright 10/10；临时服务随后关闭，未复用旧预览。

## 未关闭门禁

- 一次性真 PostGIS 上的 001–015 全迁移、补偿和重放尚未实际执行。
- 官方线路几何、上下客点、方向、班次、服务名称、票价、末班、即时排队和停运责任源未取得。
- 无障碍需逐段核验站点、衔接步道、车厢/轿厢及工作人员协助流程。
- 短期运营快照、离线包重签/撤回、真机弱网和现场换乘演练尚未完成。

因此，本交付证明的是多模式导航软件控制和数据契约，不证明任何现实交通服务正在运行或可安全使用。
