## 2. 项目定位结论

六祖云游不是景区官网、普通攻略站或独立虚拟地图，建议继续坚持：

> 在真实、可核验的景区空间之上，以可替换文化视觉层、受控 AI 行程结构化和有来源的现场导览，把有权处理的游记或需求转化为可以确认、执行、讲解、保存和分享的旅程。

长期平台化可以保留在数据与模块边界中，但六祖镇首版只验证一个真实、可信、可运营的闭环，不提前建设全国 SaaS、完整社区或商业生态。

## 3. 六祖镇真实世界结论

### 已确认

- 六祖镇、六祖故里旅游度假区、国恩寺核心区和扩展“禅意之旅”点位群是四个不同层级，不能混成一张没有边界的“景区地图”。
- 国恩寺是全国重点文物保护单位，同时是活态宗教空间；讲解、拍摄、声音、位置触发与游戏化必须服从文保、寺院和运营规则。
- 官方线路连接惠能广场、禅域小镇、国恩寺、藏佛坑等多个点位，但现有证据不能证明它们是一条连续可步行路线。
- 高德候选坐标显示国恩寺到禅域小镇直线约 5.64 km；藏佛坑出现两个相距约 1.07 km 的同名候选。所有坐标仍需第二来源、景区方和现场入口核验。
- 2025 年底新兴南站启用并有国恩寺方向接驳线；具体站点、班次、票价与临时调整必须接入实时来源或上线前复核。
- 2026 年春节官方初步统计支持“周边城市短途、自驾、高峰”是重要场景，但只代表 9 天假期，不可外推全年用户画像。

### 仍需外部闭合

- 4A 景区、开放游览区、文保与宗教场所的正式边界和可发布 GIS 数据；
- 核心入口、内部道路、步道、坡度/台阶、无障碍、设施、弱网、安全与临时封闭；
- 国恩寺讲解、礼仪、拍摄、音频和互动边界；
- 开放、停车、公交、客流、活动与应急状态的责任人和更新机制；
- 既有信息化系统、设备、合同、账号、接口、数据产权与网络安全整改结果；
- 官方客流/收入统计之间的口径冲突说明。

这些不是 Gate 1 必须已经取得的生产文件，但必须在进入蓝图时成为有责任人、有完成时点的依赖；在闭合前继续阻止正式开工或上线承诺。

## 4. 推荐的 Gate 1 决策包

### G1-01 第一版核心用户

**推荐：** 先服务自驾或高铁到达、希望在有限时间内完成国恩寺及相邻核心区体验的独立游客/家庭；同时把景区运营和文化审核人员视为支撑该体验的必要 B 端用户。

第二优先：六祖文化深度/研学用户。  
后续：两天一夜“禅文化 + 温泉”游客。

### G1-02 首发体验边界

**推荐：选项 A——经管理方确认的核心文化与服务区。** 候选包含游客中心、国恩寺、龙潭湖和已核实开放的步道片段，最终以正式边界/入口/路径为准。

- 六祖故居、藏佛坑、惠能广场等先作为扩展点位候选；
- 禅域小镇、温泉、民宿和香荔农旅先作为跨点位/两天一夜场景；
- 不把全镇、全部乡村或官方宣传线路自动当成首发连续导航区。

### G1-03 完整价值 MVP 与验证顺序

**推荐保留完整差异化闭环：**

`导入有权处理的游记/自然语言需求 → 提取地点与时间证据 → POI 消歧并让用户确认 → 真实路线计算 → 前台/手动到点讲解 → 轻量打卡 → 保存并私有/链接分享`

执行时分成两个内部验证切片，但都属于同一 MVP 蓝图：

1. **现场可信切片：** 到达、正确入口、标准二维地图、真实路径、设施/状态、讲解、异常与保存；
2. **差异化切片：** 游记结构化、用户确认、行程调整、地图执行、打卡和私有/链接分享。

只做第 1 项可称 PoC，不能悄悄替代完整价值 MVP。

### G1-04 地图与载体原则

**推荐原则：**

- 公开道路导航与景区内部导览网络分层，只有经核验入口可以连接两层；
- 先把已配置的高德作为中国境内 PoC 候选，并与百度/必要的主题渲染方案用同一批点位比较；当前不锁供应商；
- H5/小程序优先验证前台地图、定位和讲解，始终提供“我已到达”、文字和标准地图回退；
- 首期不承诺 H5 锁屏/后台持续导航，不默认缓存厂商瓦片、POI 或路线；
- 地图商用、审图、资质、坐标、缓存/离线、数据地域、SLA 与费用在蓝图阶段书面核验。

### G1-05 AI 导游原则

**推荐原则：**

- 首期采用受控单编排和少量只读白名单工具，不做多 Agent 扩张；
- LLM 负责理解、提取、解释和候选，不创造坐标、路线、开放、安全或实时事实；
- 文化内容按史实、宗教传统、民间传说、解释和营销分层；每项保留来源、许可、审核人、版本与有效期；
- 无证据即明确拒答，来源冲突则并列展示；
- 核心讲解优先人工审核后的真人录音或预生成语音，临时追问再小范围验证实时 TTS；不持续监听麦克风；
- 精确轨迹端侧优先，默认不上传/长期保存连续原始轨迹；
- “禅小荔”定位为知识问答/数字导游助手，不冒充宗教权威，不做持续情感依赖型陪伴；上线前由法务复核。

### G1-06 视觉方向

**推荐组合：**

- 现场导航主方向：A「岭南禅径」；
- 行前、行后、路线章和分享：少量 B「香荔旅行手账」；
- C「东方数字禅境」延后到云游/沉浸模块被明确验证之后。

真实道路、方向、位置、设施、风险和标准地图回退永远高于水墨、贴纸、IP 和动效。历史讨论中的 `70/20/10` 只作为设计实验，不是固定规范。

### G1-07 Logo/IP 与外部媒体

**推荐：** 现有 Logo 和“禅小荔”仅作蓝图阶段内部视觉参考；在权利人、定稿、商用/改编/公开部署授权和矢量/分层源文件齐全前，不作为可发布生产资产。

政府、景区、旅游平台和社交页面的图片/视频许可不明时，只留来源链接和拍摄/授权需求，不下载、不描摹、不进入产品。正式媒体优先由项目/景区自有授权、委托实拍或逐项购买取得。

### G1-08 分享与内容生产

**推荐：** 第一版普通游客内容默认私有或链接分享，不开放公共社区、排行榜或商业售卖。专业导游内容生产可在后续蓝图预留，但公开推荐前必须有权利合同、逐点编辑、文化审核、路线实走、版本和下架机制。

### G1-09 商业验证目标

**推荐首期只验证：**

1. 游客能否更容易到达、少迷路并理解六祖文化；
2. 管理方能否维护真实地图、开放状态与审核内容；
3. 游记能否安全转化为经用户确认、可执行的路线；
4. 六祖镇能否沉淀可复用数字资产。

首期不引入支付、广告、商城或导游路线售卖；任何长期付费 API、商业软件和云资源仍须单独确认。

### G1-10 明确延后

- 全 3D 数字孪生；
- AR 寻宝或国恩寺核心区游戏化；
- 完整剧情/游戏、完整社区、排行榜；
- 商城、直播、广告与复杂支付；
- 全镇全域导航、多景区 SaaS 后台；
- 长时后台语音监听、多 Agent 自主执行。

## 5. 进入第二阶段后的交付与限制

用户明确批准 Gate 1 后，第二阶段才生成：

- 产品：PRD、用户流程、功能地图、完整 MVP 与版本边界；
- 技术：系统架构候选、数据模型、数据库设计、API、部署、安全、隐私和内容治理；
- 设计：UI 规范、页面结构、地图皮肤与无障碍/降级规则；
- 研发：PoC、Sprint、测试、验收、资源获取和外部依赖计划。

第二阶段仍不写产品代码、不创建数据库、不采购服务。完成蓝图后必须再次获得用户明确确认，并通过需求、API、资源、设计、数据库与环境六项开工验收，才允许进入 Implementation。
