# 景区智能导航 N19 前台确定性关键语音交付报告

日期：2026-08-16  
结论：软件闭环完成；生产仍为 `NO_GO`

## 1. 修复的问题

正式逐向导航已有路线修订、下一步文字、剩余距离、定位置信度和页面生命周期控制，但此前没有与这些安全状态共用同一事实源的关键语音。若直接朗读每次 GPS 更新后的动态文字，会造成重复播报；若不绑定路线版本、路段和页面生命周期，还可能在低精度、偏航、版本失效或页面后台继续播放旧指令。

## 2. 当前实现

- 语音默认关闭，只能由游客在本次页面会话中显式开启；不跨刷新或页面持久化。
- 全局静音优先。开启全局静音会立即取消并关闭本次导航语音；之后取消静音也不会自动重新开启。
- maneuver 只取自当前 `FormalNavigationRuntime`，语音身份同时绑定路线指纹、正式道路边和 maneuver 类型；服务端错误、坐标、版本值和日志不会直接进入语音。
- 曲线边内的造型点共享同一正式道路身份。路段几何与 traversal 段数漂移时语音失败关闭，不猜测当前路段。
- 同一正式路段按距离分档去重，只允许在进入更近分档且距上次播报至少八秒时重播；GPS 抖动回到更远分档不能恢复旧提示。
- 新路线指纹、正式道路边或转向/索道/观光车语义变化可以立即生成新提示。
- 后台/冻结、手动暂停、等待定位、低精度、跳点、偏航、反向、运营版本变化、退出和到达都会先取消旧语音。退化、安全和到达状态只使用固定白名单提示。
- 导航只在自己已提交播报时持有页面语音播放权；导航语音未开启或没有导航播报时，不会用全局 `cancel()` 误停“禅小荔”等其他页面朗读。全局静音仍按用户意图停止全部语音。
- 回前台仍服从 N18：重新核验完整正式快照、游客显式确认、重新建立前台定位并取得新的可靠样本后才允许继续语音。
- 使用浏览器本机 `speechSynthesis`，不请求麦克风，不录音、不上传音频，也不保存播报文本、时序或语音选择。浏览器不支持或播放失败时只降级为文字、地图、方向和现场标识。
