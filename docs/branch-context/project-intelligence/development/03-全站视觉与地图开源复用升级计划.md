# 全站视觉与地图开源复用升级计划

状态：`APPROVED_DIRECTION / IMPLEMENTATION_PENDING`  
版本：V1.0（GitHub 调研整合版）  
更新日：2026-08-15（Asia/Shanghai）  
适用范围：全站视觉重设计、禅小荔 2.5D 助手、Hero 视频、真实地图与景区路网、地图风格、真实媒体资产。

## 1. 计划结论

本轮不整体 Fork 或移植任何现成地图产品。项目继续保持现有 `Next.js + React + MapLibre + PostgreSQL/PostGIS` 主体，只引入与现有架构互补、许可证可控且能够被替换的能力：

1. `Terra Draw`：候选的景区后台几何编辑能力；
2. `Maputnik`：应用外地图样式工作台，只输出 MapLibre Style JSON；
3. `PMTiles`：景区建筑、道路、POI、水系、地标和艺术图层的静态矢量瓦片分发；
4. `Martin`：PostGIS 到矢量瓦片/PMTiles 的构建与发布工具候选；
5. `pgRouting`：经景区核验的内部路网计算首选；
6. `高德地图`：中国境内公共道路、公共 POI、搜索和到核验入口的正式候选；
7. `GraphHopper`：自托管公共 OSM 步行路由的隔离 PoC，不直接并入前端；
8. MapDraw、uMap、GraphHopper Maps、OpenIndoorMaps、Husky Navigation、Organic Maps、MapStore2 只进入交互参考库，不复制源码或整套 UI。

核心原则是“借成熟能力加速，但保留自己的产品、数据和发布责任”。任何引擎都不能把未核验 OSM 小径、POI 中心点或模型生成路线自动提升为景区正式可通行路线。

### 2.3 延后候选

- [Valhalla](https://github.com/valhalla/valhalla)：未来需要山地步行、海拔、多模式或原生区域离线路由时，与 GraphHopper 同数据集比较。
- [OSRM](https://github.com/Project-OSRM/osrm-backend)：未来公共道路高吞吐或大矩阵需求明确后再评估。
- [OpenTripPlanner](https://github.com/opentripplanner/OpenTripPlanner)：只有景区接驳车、公交、GTFS 与实时班次成为正式范围时再立项。

## 3. 目标架构

```text
景区运营后台
  └─ Terra Draw 候选编辑器
       └─ 草稿点/线/面 + 来源 + 权利 + 核验状态
            └─ 审核/发布/撤回
                 └─ PostgreSQL + PostGIS
                      ├─ pgRouting：内部正式路网
                      └─ Martin：MVT / PMTiles 构建

游客端 PWA
  ├─ 标准地图：高德公共底图/POI/公共路线
  ├─ 景区叠加层：核验 POI、入口、设施、内部线路、实时状态
  ├─ 艺术地图：MapLibre + PMTiles + Maputnik Style JSON
  ├─ 内部路线：InternalRouteProvider → pgRouting
  ├─ 公共路线：PublicRouteProvider → 高德
  └─ 开源对照 PoC：PublicRouteProvider → GraphHopper
```

坐标主库保留原始值、CRS、来源、转换版本和核验记录。内部权威数据以 WGS84/既定主坐标契约保存；高德所需 GCJ-02 只在供应商边界转换，不覆盖原值。地图主题只能改变视觉，不能改变路线几何、入口、开放状态或安全判断。

## 4. 全站视觉与页面范围

现有 13 个页面全部重新设计，并新增 2 个地图页面，共 15 个页面画板与对应移动/桌面状态：

1. `/` 首页；
2. `/map` 游客地图；
3. `/arrival` 到达与入口；
4. `/plan` 行程规划；
5. `/guide` 现场导览；
6. `/guide/ask` AI 导游问答；
7. `/cloud-tour` 云游；
8. `/journey` 我的旅程；
9. `/journey/knowledge` 知识收藏；
10. `/share` 分享查看；
11. `/account` 账户；
12. `/privacy` 隐私与数据；
13. `/admin` 运营后台；
14. `/admin/readiness` 发布准备度；
15. `/admin/map-editor` 景区地图编辑器。

视觉流程保持：先用 ImageGen 生成 3 套全局方向板和关键页全尺寸稿，再选定统一方向；随后在 Figma 建立 token、组件、15 页及关键状态，最后才按画板重构代码。推荐默认方向为“岭南禅径”：真实景区摄影为主体，温润石色、荔枝红、竹青和香槟金为辅助；水墨只作环境层，科技感只作 AI/定位状态，不以通用紫色渐变替代地域表达。

页面统一使用全站 4 项任务导航：`首页 / 行程 / 地图 / 我的`。云游、AI 导游、现场导览是页面内任务入口；后台使用独立导航。设计必须覆盖空、加载、失败、离线、权限拒绝、低精度、过期、撤回、无数据和无障碍状态，而不是只画理想首屏。

## 5. 地图产品改造

### 5.1 三层数据责任

1. 公共地图层：由高德等合规供应商展示道路、建筑、公共 POI、搜索和到景区入口的路线；
2. 景区权威层：由本项目展示管理方确认的边界、入口、设施、景点、内部道路、无障碍属性和临时状态；
3. 艺术表达层：由 MapLibre/PMTiles/Style JSON 呈现禅意、夜游和手账风格，不制造新地理事实。

### 5.2 四种地图风格

- 标准详图：高信息密度、完整标注、搜索、设施分类、标准路线；
- 岭南禅意：保留所有导航可读性，使用石色、竹青、水墨纹理和寺院/山水母题；
- 夜游安心：暗色低眩光、路线和安全设施高对比；
- 香荔手账：用于行前规划和云游，不用于高风险现场路线判断。

ImageGen 负责先画风格目标图；Maputnik/Style JSON 负责可落地的地图样式；不把整张 AI 图片当作可导航地图，也不把高德截图描摹成自有地图。

### 5.3 后台编辑与发布

`/admin/map-editor` 的第一版只支持候选草稿：

- 点：景点、入口、设施、求助点、触发点；
- 线：公共连接候选、内部步道、无障碍路线、临时封闭；
- 面：景区边界、功能区、不可进入区；
- 属性：来源、权利、CRS、精度、核验人、核验日、有效期、坡度、台阶、路面、方向和开放状态；
- 操作：吸附、路口切分、撤销/重做、导入/导出、差异预览、提交审核；
- 门禁：编辑器绝不直接修改已发布网络，发布必须生成新 revision 并可撤回。

## 6. 禅小荔、Hero 视频与真实素材

### 6.1 禅小荔

现有 10 张动作图是带烘焙背景的 2D 渲染，不是假定可直接生产真 3D 的模型。首版采用可落地的 2.5D 状态角色：先抠图和统一造型，再建立待机、聆听、思考、回答、规划、提醒、拖动、缩边、错误和静音等状态。全站以浮动助手出现，支持单击问答、拖动、缩边、双击历史、按住说话；气泡定时收起，输入框保持紧凑。真 3D 需另行重建模型、骨骼、表情和性能预算，不阻塞首版。

### 6.2 Hero 视频

用户提供的 10 秒 1280×720 视频用于首页 Hero 背景：自动循环、静音、内联播放，提供海报帧、低带宽降级和减少动态模式；文字区增加渐变遮罩保证可读性，移动端按主体安全区裁切。

### 6.3 真实媒体

只保存明确允许下载和产品复用的原图/视频；许可不明的素材只记录页面、发布方、访问日、用途和版权状态，不镜像到产品。每个正式景点建立“远景、入口、建筑细节、内部空间、人物活动、季节/时段、无障碍与服务设施”素材槽，避免一处景点只有一张图。所有生产媒体进入 manifest，记录来源、作者/机构、许可、修改权、署名、hash、裁切版本和撤回状态。

## 7. 实施顺序

### Wave 0｜安全快照与开源台账

- 保留当前脏工作树，不重置用户文件；
- 建立第三方清单、许可证/NOTICE、固定版本或 commit、SBOM；
- 建立 `MapProvider`、`PublicRouteProvider`、`InternalRouteProvider`、`TileProvider` 适配器边界；
- AGPL 项目只做行为研究，禁止复制源码。

### Wave 1｜视觉母版与 Figma

- ImageGen 输出 3 套全局视觉方向和首页/地图/导览/IP 助手关键参考图；
- Figma 建设计 token、栅格、全局导航、地图控件、卡片、表单、状态组件和 15 页画板；
- 完成桌面、390px 手机、横屏、字号放大、减少动态和高对比版本。

### Wave 2｜地图基础 PoC

- Terra Draw × MapLibre 6.3 兼容测试；
- 当前 GeoJSON 与 PMTiles 同数据性能对比；
- Maputnik 产出 4 套 Style JSON，检查字体/sprite/数据源权利；
- PostGIS → Martin/PMTiles 构建链验证；
- 失败则保持现有地图可运行，不用 PoC 破坏主线。

### Wave 3｜游客地图与全站视觉重构

- 新建 `/map`，首页 `#map` 保留为兼容入口并跳转；
- 接入高德标准详图、搜索、公共 POI 和到核验入口路线；
- 叠加自有景区图层、图例、筛选、详情、状态和来源；
- 逐页按 Figma 重构，不改变既有账户、分享、行程、导览和治理契约。

### Wave 4｜景区编辑器与路网发布

- `/admin/map-editor` 接入 Terra Draw 草稿编辑；
- 保存 PostGIS 草稿，执行拓扑、连通、跨层、入口、权利、有效期和审核校验；
- 形成 draft → review → publish → withdraw 版本链；
- PMTiles 只从已发布数据构建，撤回后更新版本与离线包状态。

### Wave 5｜路线与导航增强

- `pgRouting` 计算已发布内部网络，支持临时关闭、方向、坡度、台阶和无障碍权重；
- 高德负责公共道路到正式入口；
- GraphHopper 使用相同入口对做隔离 PoC，比较路线、转向、海拔、地图匹配、成本和运维；
- 前端借鉴 GraphHopper Maps/Organic Maps 的路线摘要、逐向卡片、低干扰导航、离线与偏航恢复；
- 正式首版只保留一个公共路线提供方，任何失败回退到已发布路线快照和“停止并核验”。

### Wave 6｜IP、视频与媒体整合

- 2.5D 禅小荔接入全局 Shell，与现有 AI 导游能力连接；
- Hero 视频与降级海报接入；
- 获授权实景素材按 manifest 接入页面、景点卡、地图详情和云游章节；
- 控制首屏体积、图片尺寸、视频码率、懒加载与离线容量。

### Wave 7｜完整验收

- 单元、契约、地图 schema、路由、缓存、撤回、权限和安全测试；
- 15 页桌面/手机/横屏视觉回归；
- 键盘、屏读、48px 触控、高对比、字号放大、静音、减少动态；
- 弱网/离线、定位拒绝/低精度、服务失败、存储失败和旧版本迁移；
- 现场路线仍需管理方数据、实走、入口/封闭/安全责任确认，代码全绿不等于正式景区导航获批。

## 8. PoC 去留标准

| PoC | 通过条件 | 失败处理 |
|---|---|---|
| Terra Draw | MapLibre 6.3 可稳定绘制/编辑/撤销；移动触控和销毁重建无泄漏；只能写草稿 | 自研最小编辑控件，不降级成 Leaflet 双栈 |
| PMTiles | 同数据下首屏/缩放/内存优于整包 GeoJSON；版本撤回和离线清理可验证 | 保留分片 GeoJSON/MVT，不影响地图主线 |
| Maputnik | 4 套 Style JSON 均能重现目标图且所有外部资源可发布 | 自建 style token，不嵌入 Maputnik |
| pgRouting | 正式小路网 0 穿墙/跨水/关闭边；无障碍权重可解释；revision 一致 | 保留人工审核路线快照，不伪装动态重算 |
| GraphHopper | 同入口集路线/转向有明确增益，OSM/运维/内存/更新成本可接受 | 继续使用高德，不保留第二套路由服务 |

## 9. 许可证与素材护栏

1. MIT/BSD/Apache 代码接入时保留版权、LICENSE、NOTICE 和来源版本；
2. MapDraw/uMap 的 AGPL 代码不复制、不改造进商业主仓；只记录产品模式并独立实现；
3. pgRouting 的 GPL 使用方式、部署与分发在公开上线前复核；
4. OSM 数据遵守 ODbL 与署名，软件许可证不替代数据许可；
5. 不复制高德底图、截图、瓦片或 POI 数据到自有离线包；
6. Organic Maps 的代码、二进制地图和白标/署名是不同许可边界；
7. GitHub 项目的品牌视觉、截图、图标、字体和演示数据不能因代码开源而自动复用。

## 10. 本轮最终决策

- **立即进入验证清单**：Terra Draw、PMTiles、Maputnik、Martin、pgRouting；
- **隔离对照 PoC**：GraphHopper；
- **正式公共地图首选仍为**：高德 + 自有核验景区层；
- **只借鉴不移植**：MapDraw、uMap、GraphHopper Maps、OpenIndoorMaps、Husky Navigation、Organic Maps、MapStore2；
- **延后**：Valhalla、OSRM、OpenTripPlanner；
- **明确禁止**：同时维护 Leaflet、OpenLayers、MapLibre 三套游客端渲染栈，或同时部署多套公共路由引擎。

这份计划替代“下载一个完整项目再改”的思路：真正迁移的是成熟组件、接口契约和经过筛选的交互模式，而不是复制另一款产品的技术债与许可证义务。
