# 版本路线图与 Sprint 计划

状态：`GATE_2_APPROVED_BASELINE`  
版本：V0.1（第二阶段蓝图）  
编制日：2026-08-14（Asia/Shanghai）  
执行边界：本文件只规划未来工作，不构成 Gate 2 通过、开工验收通过或 Implementation 授权。

## 1. 路线图结论

项目采用“先消除现场风险，再完成差异化价值”的顺序，但两个切片共同构成首版完整 MVP：

1. **现场可信切片（PoC/高风险验证）**：到达、正确入口、标准二维地图、真实路径、设施与状态、有来源讲解、异常处理和保存；
2. **差异化完整 MVP 切片**：导入有权处理的游记或自然语言需求，保留原文证据，完成 POI 消歧和用户确认，生成真实路线并执行，完成轻量打卡、保存和私有/链接分享。

只完成第 1 项时，交付物只能称为“现场可信 PoC”，不能称为完整 MVP，也不能用它替代第 2 项。范围基线来自《[Discovery 审核包](../handoffs/Discovery审核包.md)》G1-01 至 G1-10。

## 2. 排期口径与假设

- “相对第 1 周”从 **Gate 2 获用户明确批准、开工前验收通过且用户明确授权编码** 后开始计算，不从本文编制日开始计算。
- 下表按每个 Sprint 约 2 个相对周作规划单位；它是依赖和节奏模型，不是合同工期或固定上线承诺。
- 假设存在可并行协作的产品、设计、前端、后端、GIS、AI/内容、测试、运维/内容审核人员，法务与隐私顾问可按门禁参与。人员不足时先减少并行量并重新估算，不压缩安全、现场和审核工作。
- 外部资料取得、寺院/文保审核、现场采集、供应商书面答复和采购周期不计入开发 Sprint 的确定工时；它们若迟到，相应工作停止而非用推测数据占位。
- 任何长期付费 API、商业授权、云资源、新供应商或核心技术路线，仍须按决策权限单独获得用户确认。
- 第一版只实施一个六祖镇实例，但数据、内容和权限边界需避免把“六祖镇”硬编码成唯一景区。

## 5. Sprint 计划

### Sprint 0｜受控工程与治理基础（相对第 1–2 周）

| 项目 | 内容 |
|---|---|
| 目标 | 在获准开工后建立可回滚、可审计、可隔离的最小工程基础，承接一个六祖镇实例但保留景区标识边界。 |
| 输入 | Gate 2 已批准蓝图、六项准备度通过记录、最终载体/候选服务决定、环境与权限清单、数据/接口契约、安全与隐私基线。 |
| 计划输出 | 开发/测试/预发布环境；最小身份与角色边界；配置和秘密管理；审计、错误、性能与成本观测；功能开关；契约测试与回滚基线。 |
| 验收 | 不在代码、日志或文档泄露密钥；环境严格隔离；角色越权用例失败；部署与回滚演练成功；日志默认不含精确轨迹、原始语音或完整游记。 |
| 阻塞关系 | Gate 2、开工验收、既有系统盘点、云/供应商/数据处理角色未明确时不得启动。 |

### Sprint 1｜权威数据、内容和运营发布链（相对第 3–4 周）

| 项目 | 内容 |
|---|---|
| 目标 | 先让“什么可以向游客发布”有来源、版本、审核、有效期和撤回能力。 |
| 输入 | 正式首发边界、POI/入口/设施候选、文化事实原子、宗教/文保规则、动态状态类型、资产权利文件和审核角色。 |
| 计划输出 | 地理/文化/状态/资产的草稿—审核—发布—过期/撤回流程；来源和版本追溯；动态状态更新与降级规则；首发数据包。 |
| 验收 | 每个发布对象可回溯来源、权利、审核人和复核日；未核验/过期对象不会进入游客端；撤回能影响检索、缓存和分享；内容事实/传统/传说/解释/营销分层有效。 |
| 阻塞关系 | 管理方数据、寺院/文保审核、动态状态责任人、Logo/IP 与媒体权利不齐时，只能保留未发布草稿。 |

### Sprint 2｜到达、入口与标准二维地图（相对第 5–6 周）

| 项目 | 内容 |
|---|---|
| 目标 | 解决自驾/高铁游客到正确范围、正确入口和核心服务点的基础可信问题。 |
| 输入 | 经核验入口和公共道路连接点、地图服务契约、公共/内部网络分层、停车/接驳/游客中心/厕所/求助资料、地图与页面设计规范。 |
| 计划输出 | 到达方式选择；范围分层；标准二维地图；入口、设施和状态；公开道路到核验入口；主题/标准地图切换；定位拒绝和低精度降级。 |
| 验收 | 公开道路和景区内部网络没有未经核验连接；POI 中心不会被当作入口；主题切换不改变路线/缩放/当前位置；动态状态显示来源和更新时间；定位被拒绝时仍可手动使用。 |
| 阻塞关系 | 正式边界、入口、地图授权/审图责任、可发布设施数据或载体 PoC 未闭合时不进入现场验证。 |

### Sprint 3｜现场路线、到点讲解与异常兜底（相对第 7–8 周）

| 项目 | 内容 |
|---|---|
| 目标 | 完成“现场可信切片”，用现场证据验证路线、定位、讲解、弱网和运营异常。 |
| 输入 | 已批准内部路线节点/边、现场轨迹、触发点、审核讲解/音频、开放/封闭流程、应急与无障碍资料。 |
| 计划输出 | 内部路线执行；前台位置/手动“我已到达”；讲解播放/文字/暂停/重播；弱网包；偏航、封闭、无法核验和求助降级；足迹保存；若载体、音频、场所规范与授权 PoC 均通过，加入可随时静音的前台关键路线语音提示。 |
| 验收 | 发布路线全部实走并获管理方确认；关键错误路线和安全误导为零；无来源讲解拒绝发布；事实/传统/传说标签可见；弱网、音频失败和位置失败均可继续核心任务；若语音提示获启用，其方向、距离和 ETA 必须来自当前 RoutePlan revision，旧路线失效时立即停止；完成现场演练。 |
| 阻塞关系 | 任一首发路线、寺院规则、讲解资产、救援/封闭责任或现场许可未完成时，相应路线不得纳入 PoC。 |

M1 评审在此发生：若现场可信 PoC 不通过，不进入差异化功能扩展；修复真实空间问题优先。

### Sprint 4｜游记/需求结构化与来源证据（相对第 9–10 周）

| 项目 | 内容 |
|---|---|
| 目标 | 把用户有权处理的内容转成“待确认候选”，而不是直接生成事实路线。 |
| 输入 | 授权与隐私规则、允许的输入类型、AI 结构化契约、POI 词典、黄金评测集和提示注入防护。 |
| 计划输出 | 文本/自然语言需求导入；地点、时间、偏好、同行/行动约束提取；逐字段原文证据；不确定项和删除入口；恶意内容隔离。 |
| 验收 | 每个提取字段能回指原文或明确标记推断；未授权/不可取得的第三方内容不被抓取；Schema 合法且语义评测达门槛；低置信和歧义不自动进入路线；原文默认不长期保存。 |
| 阻塞关系 | 输入权利告知、删除链、模型/DPA、评测集和日志最小化未通过时不得开放真实用户试用。 |

### Sprint 5｜POI 消歧、行程编辑与真实路线联动（相对第 11–12 周）

| 项目 | 内容 |
|---|---|
| 目标 | 让用户确认地点、入口、交通和约束后，才生成可执行行程。 |
| 输入 | Sprint 4 候选、经核验 POI/别名/入口、公共与内部路由、开放状态、行程编辑与地图契约。 |
| 计划输出 | 多候选对比、来源和距离说明；用户确认/更换/删除；顺序/停留/交通编辑；路线重新校验；不可达和过期状态拦截。 |
| 验收 | 重名、双候选、旧称和无匹配用例均不会静默选择；编辑后重新校验所有路段；LLM 不生成路线几何或开放事实；不可达时正确拒绝并给出权威替代通道。 |
| 阻塞关系 | POI 第二来源和现场核验、路由许可/缓存边界、动态状态有效性不足时只允许受控测试数据。 |

### Sprint 6｜打卡、保存与私有/链接分享（相对第 13–14 周）

| 项目 | 内容 |
|---|---|
| 目标 | 完成从内容输入到旅程执行和可控分享的完整 MVP 闭环。 |
| 输入 | 可执行行程、到点事件、内容/资产权利、用户账户/匿名策略、分享与生成内容标识规则。 |
| 计划输出 | 轻量打卡/知识卡收藏；行程和足迹保存；默认私有；最小化链接分享、失效/撤回/删除；来源和 AI 标识随内容保留。 |
| 验收 | 不以宗教行为换积分；未到点可手动记录但不冒充自动证据；默认不公开精确轨迹；分享链接可撤回并在撤回后失效；原游记/第三方媒体不会被无权复制；不含公共社区、排行、售卖或支付。 |
| 阻塞关系 | 分享隐私、第三方内容引用、未成年人和生成标识规则未获法务/责任人确认时，仅保留本地/私有保存。 |

### Sprint 7｜整合硬化与受控现场 Beta（相对第 15–16 周）

| 项目 | 内容 |
|---|---|
| 目标 | 用真实设备、真实网络和真实运营人员证明完整 MVP 可用、可维护、可降级。 |
| 输入 | 两个切片集成版本、设备/网络矩阵、现场权限、运营/内容人员、隐私影响评估、应急演练计划。 |
| 计划输出 | 端到端回归；长者/家庭/无障碍测试；弱网/断网/低定位精度；内容/状态更新与撤回演练；模型/地图/服务故障演练；受控 Beta 记录。 |
| 验收 | 发布级 P0/P1 缺陷清零；关键安全/事实错误为零；目标设备和网络达到 Gate 2 已确认阈值；运营人员可在约定时限内更新/撤回；参与者数据按同意和保留期处理。 |
| 阻塞关系 | 现场测试许可、真实设备/运营商覆盖、无障碍参与者、安全保障或运营值班未准备时不得开展 Beta。 |

### Sprint 8｜发布候选、移交与运营准备（相对第 17–18 周）

| 项目 | 内容 |
|---|---|
| 目标 | 形成可供项目方决定是否发布的证据包，不自动上线。 |
| 输入 | Beta 结果、缺陷清单、内容/资产发布清单、性能/成本/容量数据、合规结论、值班与回滚方案。 |
| 计划输出 | 发布候选版本；运行手册；监控/告警/成本阈值；备份恢复/回滚；内容与资产 manifest；培训、客服、投诉、纠错和事故响应材料。 |
| 验收 | 所有发布对象可追溯且权利未过期；发布/回滚/撤回演练成功；容量和成本在用户批准范围；安全、隐私、AI 标识、地图标识和内容审核签字齐全；项目方另行批准发布。 |
| 阻塞关系 | 法务/合规、权利、内容、现场、SLA、预算或重大缺陷任一未关闭时不得公开发布。 |

## 6. 横向工作流

| 工作流 | 贯穿阶段 | 强制产物 |
|---|---|---|
| 证据与内容治理 | Sprint 1–8 | 来源、类型、审核、版本、有效期、撤回与回归记录 |

## 7. 范围护栏

首版明确不进入 Sprint：全 3D 数字孪生、AR 寻宝、国恩寺核心区游戏化、完整剧情/游戏、公共社区/排行榜、商城/直播/广告/复杂支付、全镇全域导航、多景区 SaaS 后台、长时后台监听和多 Agent 自主执行。

若有人提出新增功能，先回答：是否增强核心体验、是否直接服务游客、是否可复用于其他景区、是否显著增加范围/成本/风险、是否有更小验证方式。中大型功能、供应商变化、长期付费、核心架构或产品方向变化必须提交用户确认。

## 8. 每个 Sprint 的通用完成定义

- 产品验收场景、异常场景和无障碍场景均通过；
- 可核验事实、地理、状态、路线、内容和资产均有来源/版本/责任人；
- 无未经批准的范围、供应商、付费或数据采集；
- 测试证据与缺陷已归档，P0/P1 缺陷按相应里程碑门禁清零；
- 安全、隐私、日志、删除、回滚和降级不以“以后补”为完成；
- 文档和决策记录已更新；
- 用户未明确授权前，任何计划输出都不能被视为已经实施。

测试细目与发布否决条件见《[测试与验收方案](../testing/01-测试与验收方案.md)》。
