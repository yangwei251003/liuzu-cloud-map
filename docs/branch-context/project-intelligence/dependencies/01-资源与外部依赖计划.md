## 1. 结论

当前项目具备完整 Discovery 研究基础，但仍不具备 Implementation 开工条件。最关键的外部依赖不是开发框架，而是：

- 首发体验正式边界、入口、内部路网、设施、无障碍和安全数据；
- 国恩寺/文保/非遗/地方史对讲解、礼仪、拍摄、声音和互动的责任与审核；
- 开放、停车、接驳、封闭、客流、应急等动态信息的权威来源、更新责任和失效机制；
- 既有信息系统、设备、合同、账号、接口、数据产权和网络安全现状；
- Logo/IP、图片、视频、音频、字体、图标等生产资产的书面权利；
- 地图、载体、AI、语音、云和数据服务的同口径 PoC、商务条款、数据地域、SLA、退出与成本决定；
- 隐私、网络安全、地图/审图、生成内容标识、拟人化互动和宗教/文保场景的法律与运营意见。

`.env.local` 中发现能力变量名，只能说明候选能力存在：`AMAP_JS_KEY`、`AMAP_SECURITY_JS_CODE`、`AMAP_WEB_SERVICE_KEY`、`GEMINI_API_KEY`。本计划不会读取、复制或记录其值；“有 key”不等于服务已验证、已选型或可商用。

## 2. 分级和状态

### 2.1 依赖级别

| 级别 | 含义 | 处理规则 |
|---|---|---|
| `B0` | Implementation 硬阻塞 | 未关闭不得开始涉及该依赖的产品开发；若影响全局真实数据/权利/合规，则不得开工 |
| `B1` | 指定 Sprint/PoC 阻塞 | 可做无关工作，但对应功能和验收不得启动或假数据转正 |
| `B2` | 发布阻塞 | 可在隔离测试中验证，但不得向公众发布 |
| `D` | Gate 2 决策项 | 需用户确认方向、候选、预算/权限或风险接受；不得由 AI 自动锁定 |

### 2.2 当前状态值

- `NOT_STARTED`：尚未发起；
- `REQUESTED`：已发出请求，等待答复；
- `PARTIAL_RESEARCH_ONLY`：只有研究/候选，不能用于生产；
- `UNDER_REVIEW`：资料已收到但权利/技术/内容未验收；
- `READY_FOR_USE`：在明确范围内完成证据、审核与版本；
- `REJECTED/EXPIRED`：不合格、撤权或到期。

当前没有任何生产级外部依赖可标为 `READY_FOR_USE`。

## 5. Implementation 前硬阻塞清单

以下任一项未关闭，Gate 2 即使批准蓝图，也不能视为允许开工：

1. 首发正式边界、入口、内部路网、设施、无障碍与应急数据没有发布级证据；
2. 国恩寺/文保/非遗文化和现场行为规则没有责任方书面审核；
3. 动态开放/封闭/停车/接驳/安全状态没有权威来源、责任人、有效期和失败降级；
4. 既有系统、合同、数据产权、账号、接口和网络安全没有盘点；
5. Logo/IP、首发媒体、讲解/声音、字体/图标的生产权利不清，且未由用户批准合法的无资产降级范围；
6. 地图、AI、语音、云/数据库候选的条款、数据地域、DPA、SLA、费用与退出风险未完成同口径评审和必要用户决定；
7. API 契约、数据模型/字典、环境/秘密/权限、备份/回滚和测试数据未准备；
8. 个人信息、地图/测绘、生成式 AI/标识、拟人化和内容合规没有书面责任结论；
9. 现场研究/采集/测试许可、安全计划和参与者数据方案未批准；
10. 用户未明确给出“蓝图确认 + 开工前验收通过 + 允许进入开发”的授权。

## 6. 获取和验收流程

### 6.1 所有资料/资产

`提出清单 → 指定机构与主/备联系人 → 收到原件/接口说明 → 登记来源与权利 → 技术/内容/现场审核 → 版本化 → 责任方批准 → 限定用途发布 → 定期复核/撤回`

资料接收表至少记录：Dependency/Asset ID、提供者、权利人、文件/接口、格式、坐标系、来源、版本、采集/发布日期、允许用途、限制、有效期、负责人、审核结果、哈希/存储位置和替代方案。

### 6.2 所有供应商

1. 用相同任务和容量表书面询价/问卷；
2. 比较功能、现场质量、资质/审图、数据地域、DPA、缓存/组合/再分发、SLA、配额、价格、支持和退出；
3. 用户确认需要付费、长期承诺、新供应商或核心技术路线的决定；
4. 合同与 DPA 审核后才创建受控 PoC/沙箱；
5. PoC 通过并记录替代/退出方案后，才可在开工验收中标为就绪；
6. 上线前用当前价格、条款和服务状态重新复核。

本阶段不得把“免费额度”“已有 key”“个人开发者账户”当作生产授权或成本承诺。

## 8. 人员与时间资源假设

计划至少需要以下能力同时存在，具体人数和工期须在团队与外部响应确定后估算：

| 能力 | 不可省略的职责 |
|---|---|
| 产品/项目管理 | 范围、依赖、决策、验收、用户/管理方协调 |
| UX/UI 与可访问性 | 户外强光、长者/家庭、标准/主题地图、异常/降级、设计验收 |
| GIS/现场采集 | 合规坐标/路网/入口/设施、实走、版本与供应商路线对照 |
| 客户端/后端/数据/运维 | 载体、接口、数据、环境、权限、监控、回滚和成本 |
| AI/知识工程 | 结构化、检索、引用、工具、拒答、评测、内容撤回 |
| 内容/文化/宗教审核 | 命题、脚本、事实类型、礼仪、专名与版本 |
| 测试/研究/无障碍 | 实验室、真机、弱网、现场、用户任务和发布证据 |
| 法务/隐私/安全/供应商管理 | 权利、个人信息、地图/AI、DPA、合同、网络安全和采购门禁 |
| 景区运营/应急/客服 | 动态更新、值班、投诉、纠错、事故与现场响应 |

若只能配置“开发人员 + 设计人员”，项目不具备完成真实景区产品的组织条件，必须缩小范围或补齐外部责任人，而不是让开发团队代签文化、路线、安全和权利结论。

## 9. 依赖管理节奏

- 每周（相对节奏）由 PM 更新依赖状态、证据链接、下一动作、主/备联系人和预计答复窗口；未取得真实联系人时不得写“进行中”。
- B0 依赖一旦延期，立即标出受影响的 Sprint/功能和安全降级，不通过加班或假数据掩盖。
- 所有动态资料按风险设复核频率；开放/封闭/应急可能需实时或当日，文化稳定事实与权利文件按版本/到期复核。
- 供应商价格、配额、条款与标准状态在 Gate 2、签约和上线前分别复核。
- 对同一事实出现冲突时保留各来源和时间，提交责任方裁决；AI 不自动合并。
- 任何已 `READY_FOR_USE` 的依赖发生撤权、过期、接口弃用或责任人失联，立即降级并重新触发门禁。

## 10. Gate 2 要求用户/项目方决定或指定

1. 首发边界和两个切片的先后顺序是否按审核包执行；
2. 景区、寺院/宗教事务、文保/非遗、交通/应急和既有 IT 的具体主/备联系人；
3. 是否授权项目方发出数据、接口、现状盘点、品牌/IP 和媒体/讲解资料请求；
4. H5/小程序、地图、AI、语音、云/数据库候选进入何种 PoC/询价范围；
5. 允许的 PoC 费用上限、长期预算原则和每项采购审批人；
6. Logo/IP 未获权利时，是继续阻塞开工，还是另行批准无 Logo/IP 的标准占位范围；
7. 是否能安排现场采集、普通日/周末/高峰候选时段研究与无障碍参与者；
8. 法务、隐私、安全、地图合规和文化审核由哪个机构/人员签字；
9. 动态信息不能实现权威实时更新时，是否接受“无法核验 + 现场渠道”的降级范围；
10. 是否同意所有 B0 依赖关闭并通过六项开工验收后，才另行授权 Implementation。
