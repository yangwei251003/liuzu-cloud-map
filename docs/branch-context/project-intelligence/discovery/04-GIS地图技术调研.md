## 1. 结论先行

1. **底图导航与景区内部导览必须分层处理。** 高德、百度、Mapbox 的步行路线只对各自道路图可达；它们不能证明六祖镇内部步道、台阶、门禁、施工封闭、无障碍条件或入口位置真实可用。首期候选形态应是“合规底图/公开道路服务 + 经景区授权与现场核验的内部步行网络”，两层只在核验过的出入口连接。[AMAP-03][BAIDU-03][MAPBOX-01]
2. **中国境内部署不能只比较画面与 API。** 地图审图、互联网地图服务资质、服务器位置、地图数据来源与个人位置保护是前置门槛；项目究竟属于持牌服务使用方、内容叠加方还是需要另行资质的服务提供者，须由地图供应商书面说明并经法务/合规确认。[REG-01][REG-02][REG-03]
3. **没有一个候选可以凭文档直接胜出。** 高德、百度更贴近境内地图生态，但六祖镇 POI、步行网络、样式许可和商务边界仍须实测/书面确认；Mapbox 样式与自有数据能力强，但境内数据合规、跨境处理与 POI/步行质量风险更高；OSM 数据开放不等于可直接使用 OSM 公共服务器，也不替代中国地图合规。[AMAP-01][BAIDU-01][MAPBOX-02][MAPBOX-05][OSM-01][OSM-02]
4. **H5 适合快速验证“看地图、查点位、前台导览”，不应承诺持续后台定位。** W3C Geolocation 对隐藏页面会暂停/丢弃位置更新，浏览器有声自动播放还受用户手势与策略限制。微信小程序可申请前后台定位，但需类目、用途、权限声明与审核；原生 App 的后台定位和离线能力最强，同时带来权限、应用商店、电量、研发和运维成本。[RUNTIME-01][RUNTIME-02][RUNTIME-03][RUNTIME-04][RUNTIME-07][RUNTIME-08]
5. **弱网策略首先应缓存自有且获授权的内容，不应默认缓存地图厂商瓦片、POI 或路线结果。** 高德、百度协议对缓存、存储、抓取、镜像、衍生和再分发设有严格限制；OSM 官方公共瓦片明确禁止批量/离线预取。离线地图若需要，应使用厂商明确授权的移动 SDK 离线能力或合规自建数据服务。[AMAP-04][AMAP-06][BAIDU-06][OSM-02]
6. **本轮高德 API 结果只是候选证据，不是坐标事实。** 受控查询未记录 key，返回为 GCJ-02；国恩寺、故居、藏佛坑、禅域小镇、温泉和度假区均出现候选，但 POI 中心不等于入口，藏佛坑有两个相距约 1.07 km 的候选，地址中“集成镇/新城镇/六祖镇”字段不一致，“惠能广场”因额度限制无结果。全部点位仍需第二独立来源、景区方和现场入口/轨迹核验，不能直接用于步行导航。

## 2. 研究问题与判定口径

本报告围绕六祖云游的真实任务比较候选方案：

- 显示中国境内合规底图，叠加景点、服务设施、文化插画和主题视觉；
- 检索 POI、把用户输入地点解析为候选、计算到景区入口的公开道路步行路线；
- 在景区内部依据真实道路、门禁、台阶、坡度、临时关闭与无障碍条件导览；
- 前台/后台定位、到点触发、弱网恢复、离线内容和语音播放；
- 坐标系、地图审图、数据授权、缓存/再分发、隐私、成本与供应商锁定。

证据口径：

- **已证实能力**：官方文档或法规明确写出；
- **待验证能力**：厂商有通用能力，但六祖镇覆盖、精度、端侧表现或商务权利未证实；
- **工程建议**：为降低风险提出的候选设计，不等同于已批准架构；
- **法务待确认**：法规/协议原文可定位，但适用性、许可范围或合同解释不能由本报告代替法律意见。

## 3. 中国境内地图、位置与在线信息合规基线

### 3.1 地图服务与审图

《地图管理条例》覆盖在中国境内编制、审核、出版地图以及互联网地图服务。公开地图原则上须送审；互联网地图服务单位向公众提供地理位置定位、地理信息上传标注或地图数据库开发等服务时涉及测绘资质要求，地图数据服务器应设在境内，新增内容也有审核/备案义务。[REG-01]

对本项目的含义不是“用了某 SDK 就自动全部合规”，而是需要在 Gate 2 前取得书面答案：

1. 谁是互联网地图服务主体，谁持资质并承担审图、备案和服务器义务；
2. 官方底图与项目自有 POI、路线、插画覆盖层各自属于何种内容，谁负责审核；
3. 厂商审图号、版权标识是否完整显示，主题皮肤是否会遮挡或改变必需标识；
4. 自建景区内部网络是否仅作为运营数据展示，还是构成需审查的地图内容；
5. 地图数据、定位数据及日志实际存储和处理地域。

以上均为**法务/供应商待确认项**，不得以本报告作法律结论。

### 3.2 位置轨迹是敏感个人信息

《个人信息保护法》把行踪轨迹列为敏感个人信息；处理敏感个人信息须有特定目的、充分必要性、严格保护措施，并取得单独同意，还应告知必要性与影响。向其他处理者提供、跨境提供、处理敏感个人信息或实施对个人权益有重大影响的自动化决策时，还可能触发单独同意、个人信息保护影响评估等义务。[REG-02]

《网络数据安全管理条例》进一步要求清晰的处理规则、最小必要、权利响应、删除/匿名化、审计及跨境条件；收集行踪轨迹等敏感个人信息需要符合单独同意要求。[REG-03]

因此 Discovery 建议的隐私基线为：

- 默认只请求“使用时”定位；持续/后台定位作为独立功能说明并单独征得同意；
- 到点判断尽量在端侧完成，只上传“触发点 ID + 粗粒度时间/状态”，默认不上传完整轨迹；
- 不以拒绝持续定位为由关闭浏览、搜索、手动选点和文字导览；
- 明确位置用途、频率、保存期限、共享方、删除入口和撤回后的降级方式；
- 上线前完成位置处理活动的个人信息保护影响评估，并核验地图/云厂商的委托处理或共同处理角色；
- 未成年人、精确轨迹、跨境传输和营销推荐另行评估。

### 4.1 不能把“厂商能力”写成“六祖镇事实”

以下结论仍然未知，必须通过 PoC、景区授权资料和现场核验得到：

- 六祖镇各名称在不同地图的命中、别名、地址、行政区与入口点；
- 景区内部步道、出入口、门禁、台阶、坡度、施工封闭、夜间通行和无障碍状态；
- 高德/百度/Mapbox 给出的步行路线是否穿越不可通行区域；
- 树荫、建筑、山体、室内/廊道对 GNSS 精度的影响；
- 不同运营商与机型的网络、定位、首屏和语音体验；
- 商用许可是否允许所需样式、覆盖层、日志、离线、缓存和供应商组合。

## 5. 公开道路导航与景区内部步行网络

### 5.1 两类网络的责任边界

| 层 | 适合解决的问题 | 不应承担的问题 | 证据/责任主体 |
|---|---|---|---|
| 地图厂商公开道路网络 | 从城市道路、停车场/公交站附近到经核验景区入口；普通公开道路步行 | 景区内部门禁、临时关闭、台阶/坡度、室内连廊、宗教活动限制、无障碍真实性 | 厂商算法与数据；项目仍需入口和路线抽查 |
| 景区内部自建网络 | 经授权的园区步道、节点、设施、讲解点、可达性、临时关闭和运营规则 | 未经授权测绘、把 POI 中心点当入口、复制厂商路线几何、宣称绝对安全 | 景区管理方 + 合规采集/制图方 + 现场复核 |

### 5.2 内部网络候选数据模型（供下一阶段评审，不是架构定稿）

每条节点/边至少应具备：

- 唯一 ID、名称/别名、原始坐标、坐标系、转换版本；
- 节点类型：入口、出口、讲解点、分叉、设施、救援/医疗/消防点；
- 边属性：方向、长度、预计步行时间、路面、宽度、坡度、台阶、照明、遮蔽、无障碍候选状态；
- 运营属性：开放时段、临时封闭、单向/限流、活动影响、紧急替代路线；
- 证据属性：来源机构、许可、采集日期、核验人、照片/工单引用、有效期、状态；
- 发布状态：草稿、现场已核验、景区已批准、暂停、过期。

“无障碍”“安全”“开放”均不得只靠模型或地图推断，必须来自景区负责部门并设有效期。

### 5.3 两层路由的连接规则

1. 只在现场确认的入口/出口节点连接公共道路与内部网络；
2. POI API 返回的代表点只作“候选中心点”，不得自动作为入口；
3. 公共路线到达点若与入口相距较远或跨越围墙/水体，必须标注并禁止自动拼接；
4. 厂商路线几何、POI 与瓦片不得复制进自建数据库，除非合同明确允许；
5. 内部网络临时关闭优先级高于历史路线；无法计算时应给出人工问询/回退，不由 LLM 编造捷径；
6. 路线页展示“数据更新时间、适用范围、现场标识优先”，紧急情况下引导联系景区人员。

## 6. 坐标、POI 与定位质量治理

### 6.1 候选坐标治理规则

在产品与技术蓝图阶段，应从以下候选规则中确认一种；本阶段不锁定数据库坐标方案：

- 每条几何保留**原始值 + 原始坐标系 + 来源 + 采集时间**；
- 转换值与转换算法/服务版本分开保存，禁止覆盖原始值；
- WGS84、GCJ-02、BD-09 在字段和接口层显式标注，不靠调用方猜测；
- 用已知控制点做转换回归测试，图层叠加误差超阈值时禁止发布；
- 入口、救援点和路线转折点采用比普通 POI 更严格的现场核验等级。

### 6.2 高德 POI 候选快照及限制

2026-08-14 的受控查询以新兴县 `adcode=445321`、`city_limit=true` 获取了高德 Place Text API 候选，未记录密钥。核心结果和问题如下：

- 国恩寺、停车场、六祖殿、报恩塔分别返回代表点；其中任何一点都不能未经现场核验成为“游客入口”；
- 六祖惠能故居及纪念馆、禅源寺、停车场出现多个相邻候选，地址字段含“集成镇/六祖镇”；
- 藏佛坑返回两个同名候选，直线距离约 1.07 km，不能自动合并或择一；
- 禅域小镇与国恩寺候选直线距离约 5.64 km，说明不能在没有路网/交通方式证据时包装成连续步行景区；
- 龙山温泉和六祖故里度假区相关候选只能证明平台返回，不证明开放、票务、运营边界或可达性；
- “惠能广场”请求触发 `CUQPS_HAS_EXCEEDED_THE_LIMIT`，本轮无结果；不得用猜测补坐标，也不继续高频重试。

完整响应摘要见独立快照。下一步最低核验链为：**地图平台候选 → 第二独立地图/开放数据 → 景区方确认 → 现场入口与步行轨迹 → 版本化发布**。

正式核验记录只保存请求日期、查询名、POI ID、候选名称、`adcode`、地址、`location`、返回坐标系与匹配置信说明，不保存 key。每个候选还须区分“POI 代表点”“建筑中心”“游客入口”“路线连接点”。

### 6.3 到点触发不能只看半径

GNSS 漂移、相邻景点和道路并行会造成误触发。候选判定应组合：

- 水平精度阈值；
- 进入半径与离开半径不同的滞回；
- 驻留时间；
- 行进方向/内部网络上的相邻节点；
- 同一讲解点冷却时间；
- 前台/后台状态；
- 明确的“我已到达”手动按钮。

位置触发只产生结构化事件，讲解内容必须来自已审核内容库；位置模型不能决定历史事实或通行安全。

## 7. H5、小程序与原生 App 比较

| 能力 | H5 / 浏览器 | 微信小程序 | 原生 App |
|---|---|---|---|
| 前台定位 | 需 HTTPS 与用户授权；精度和高精度请求由浏览器/设备决定，不能保证 | `wx.startLocationUpdate` 可在前台连续更新，需类目、用途和用户授权审核；可声明 WGS84/GCJ-02 | 系统定位能力最完整，可配置精度与更新策略；仍需按需授权 |
| 后台持续定位 | **不可靠**：W3C 规定隐藏文档不持续交付更新，不能承诺锁屏/切后台连续导航。[RUNTIME-01] | 官方有后台定位接口，但需 `scope.userLocationBackground`、`requiredBackgroundModes`、符合旅游类目用途并通过审核；插件不支持。[RUNTIME-03] | iOS/Android 均可在满足能力声明、权限与系统策略后后台定位；系统仍可能限频、暂停或终止，且耗电/商店审核压力最大。[RUNTIME-07][RUNTIME-08][RUNTIME-09] |
| 语音播放 | 有声自动播放受用户手势/浏览器策略限制；宜由用户先点击“开始导览”。[RUNTIME-02] | 已播放音频可按声明继续后台播放，但后台不可任意控制播放；不能假设切后台后可新触发讲解。[RUNTIME-05] | 播放控制最强，可与后台音频会话结合；需处理来电、耳机、系统中断与版权 |
| 录音 / ASR | 浏览器授权与兼容性差异大；噪声、断网和切后台需降级 | 有录音管理 API；不应据此推断可持续后台识别，适合按住说话/单次录音。[RUNTIME-06] | 推按说话、流式 ASR 和端侧能力更灵活；隐私与后台麦克风审核最严格 |
| 弱网内容 | 可缓存自有壳与自有内容，但地图瓦片/接口受厂商协议和浏览器缓存约束 | 可缓存包内或授权下载的自有内容；包体、更新、后台和地图条款需实测 | 可用厂商授权离线包、自有内容包和更完整的断点续传 |
| 发布成本 | 最低、迭代快 | 中等；受微信类目、隐私接口和版本审核约束 | 最高；双端开发、商店、权限、兼容与持续运维 |
| 适合验证 | 看图、查点、前台路线、手动/前台到点讲解 | 微信内导览、经审核的前后台定位验证、轻量语音 | 长时后台导航、强离线、复杂音频与深度系统集成 |

**Discovery 候选建议：** 首期可优先验证 H5/小程序前台体验，且必须提供手动到点与文字降级；是否需要后台持续定位、离线地图和原生 App，要由真实游览时长、弱网测试、用户研究和商业目标共同决定，不能因技术“能做”直接扩张范围。

## 8. 弱网与离线候选策略

### 8.1 可优先准备的自有离线内容

- 已获授权、已审核的景点文字、缩略图、讲解音频与无障碍说明；
- 景区批准的内部路线图、入口/设施/救援点和版本号；
- 当前行程、最近一次有效路线摘要、手动导览清单；
- 离线状态说明、更新时间、紧急电话与现场服务点。

### 8.2 不得默认缓存的内容

- 高德/百度/Mapbox 的底图瓦片、POI、地理编码和路线几何；
- OSMF 公共瓦片的批量/离线下载；
- 来源或许可不明的图片、路线、讲解音频；
- 实时开放、客流、天气结果的长期副本。

是否可缓存必须逐产品、逐 SDK、逐用途以当前合同为准，而不是依据技术上“抓得到”。

### 8.3 降级顺序

1. 在线底图 + 在线公开道路路线 + 最新内部网络；
2. 底图不可用时，显示已授权内部示意图、当前位置精度和文字节点顺序；
3. 定位不可用时，允许手动选择“我在这里/我已到达”；
4. TTS 不可用时播放已缓存审核音频；音频也不可用时显示文字；
5. 开放/安全实时信息不可确认时，明确“当前无法核验”，引导现场工作人员，不沿用过期结果。

## 9. 成本与供应商锁定

### 9.1 总成本构成

月度地图成本不只是 API 请求费，应至少测算：

`商业授权 + 地图显示量/MAU + POI/地理编码 + 路线请求 + 定位/导航会话 + 离线下载 + CDN/流量 + 现场采集与复核 + 审图/合规 + 监控客服 + 迁移预留`

高德商业许可与额度需按具体产品询价；百度官方 FAQ 的公开授权价格只能作时效性线索；Mapbox 按请求、MAU、行程和离线瓦片等动态计量；OSM/自有方案虽可能没有相同的许可费，但把成本转移到数据、服务器、路由、更新、SLA 和合规团队。[AMAP-05][BAIDU-07][MAPBOX-06][OSM-02]

### 9.2 Gate 2 前统一询价口径

向所有候选供应商提供同一张容量表：

- 月活/日活、单次游览时长、地图加载次数；
- 每用户 POI、地理编码、步行路线和重算次数；
- 前台/后台定位分钟数、导航会话/行程数；
- 在线/离线瓦片范围、缩放级别和下载用户数；
- 自有覆盖层体量、更新频率和多景区扩展量；
- 峰值 QPS、SLA、技术支持、日志保存地域；
- 商用、白标、多租户、二次分发、截图/导出和灾备权利。

价格、配额与条款在选型前和上线前各复核一次，不把本报告中的网页价格写入长期预算。

## 10. 候选组合路径（不构成选型）

| 路径 | 组成 | 适合验证的假设 | 主要风险 |
|---|---|---|---|
| A. 境内地图厂商底图 + 自有内部网络 | 高德或百度显示/公开道路/POI；景区授权内部路线与文化层 | 是否能以较低境内合规摩擦完成真实导览 | 厂商协议组合限制、内部采集、样式自由度、锁定 |
| B. 合规渲染器 + 全量授权自有景区数据 | Mapbox 类渲染或其他合规渲染器；自建景区数据 | 是否需要更强视觉表达和多景区数据控制 | 中国审图/跨境/覆盖/合同、路由与数据运维成本 |
| C. 自建 OSM/自有数据服务 | 自建瓦片、地理编码/路由、景区数据 | 是否有长期平台规模足以承担完整地图能力 | 资质、审图、ODbL、数据质量、SLA 和团队成本最高 |
| D. 前台轻导览验证 | 合规底图 + H5/小程序前台定位 + 手动到点 + 缓存自有内容 | 首期核心价值是否成立，无需先承诺后台导航 | 用户可能期望更连续的导航；需明确产品边界 |

当前证据支持先验证 A 与 D 的可行性，同时保留 B/C 作为对照；这只是**PoC 排序建议**，地图厂商和载体仍需用户在 Gate 1/2 确认。

## 11. PoC 验收矩阵

必须用同一批真实点位、相同设备和相同时间窗口对候选测试：

| 测试组 | 最低证据 |
|---|---|
| POI | 官方名称/别名、返回地址/adcode/坐标系、候选中心与现场入口误差、错误匹配率 |
| 公开步行 | 入口连接正确率、穿墙/跨水/封闭错误、预计时间偏差、无名道路表现 |
| 内部网络 | 现场轨迹、路口/台阶/坡度/门禁、可达性、临时封闭和景区签字确认 |
| 定位 | 开阔/树荫/建筑/廊道精度分布、首定位时间、漂移、断网恢复、电量 |
| 到点触发 | 漏触发、误触发、重复触发、相邻点串扰、前后台差异、手动降级成功率 |
| 视觉 | 不同缩放级别可读性、法定标识/审图号、主题皮肤与普通地图切换、色弱/长者可读性 |
| 弱网 | 2G/高延迟/断网/恢复、缓存命中、内容版本、过期信息拦截、音频降级 |
| 协议/合规 | 商用授权、缓存/离线/自有层/组合、数据地域、DPA、审图与资质责任书面答复 |
| 成本 | 按统一容量模型给出的阶梯成本、超额费、SLA、支持与退出/迁移成本 |

## 12. Gate 1 待用户确认与未闭合证据

### 12.1 建议用户确认的方向

1. 是否同意把“公开道路导航”和“景区内部导览网络”作为两个证据与责任层；
2. 是否同意首期不承诺 H5 后台持续定位，并保留手动到点与文字降级；
3. 是否授权下一阶段对高德、百度和必要的渲染器候选做同口径 PoC/询价，而非现在锁定；
4. 是否由景区指定路线、开放、安全、无障碍和应急信息责任人；
5. 是否允许在获得书面授权后开展现场轨迹/入口采集，并确定个人轨迹最小化方案。

### 12.2 阻塞选型的证据缺口

- 六祖镇官方 POI/设施/出入口/步道清单与可发布授权；
- 核心点位的第二来源、景区方与现场入口核验；
- 三端弱网、定位、音频与后台行为实机测试；
- 高德/百度/Mapbox 商用报价、SLA、地图审图/资质责任、数据地域与缓存/组合权利书面答复；
- 景区内部道路采集主体和地图内容合规意见；
- 目标上线日期，以判断 LB/T 014-2026 的正式适用状态。

在上述缺口闭合前，本报告不推荐签约、不推荐迁移、不推荐将任一候选写入核心架构。
