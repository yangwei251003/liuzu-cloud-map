# AI 导游 Agent 方案研究

状态：`READY_FOR_GATE_1_REVIEW`  
研究基准日：2026-08-14  
阶段边界：Discovery，只定义可验证的任务、治理与候选演进路径，不锁定模型、向量库、语音厂商、云平台或 Agent 框架。

> 证据索引：正文中的 `[REG-*]`、`[STD-*]`、`[AI-*]`、`[RUNTIME-*]` 均指向《[GIS 与 AI 官方来源](../source/ledgers/GIS与AI官方来源.md)》。地图与位置边界见《[GIS 地图技术调研](04-GIS地图技术调研.md)》。

## 1. 结论先行

1. **首期不需要“多 Agent 团队”。** 六祖云游的核心可以由一个受控编排层完成：结构化游记、检索已审核知识、调用少量只读工具、生成带引用的回答、触发审核过的讲解。拆成多个自主 Agent 会放大延迟、成本、追踪和权限风险，除非后续评测证明存在清晰收益。[AI-02][AI-09]
2. **LLM 不负责创造地图事实。** 坐标、入口、步行路径、距离、开放状态、天气、客流和应急信息必须来自已核验数据或实时工具；模型只负责理解意图、解释结果和提出候选。路线几何由地图/内部路网服务计算，位置触发由确定性规则判断。
3. **RAG 的关键是知识治理，不是“把文件丢进向量库”。** 每条知识要有来源、许可、事实类型、适用景点、核验人、版本、有效期和发布状态；官方事实、宗教传统、地方传说、营销描述和游客体验必须分开。检索命中不等于结论正确，仍需语义验证和引用一致性评测。[AI-01][AI-05][AI-09]
4. **所有可核验陈述都应显示出处和核验时间。** 无充分证据时明确回答“暂无已核验资料”，不补全、不合理猜测；实时/安全类问题若工具失败则降级到景区官方渠道，不沿用过期结果。
5. **核心景点讲解优先采用人工审核、预先生成或真人录制并可离线缓存的音频。** 即时 TTS 适合用户临时追问，ASR 首期只宜“按住说话/一次一问”，并始终保留文字入口。这样能降低弱网、发音、隐私、浏览器自动播放和成本风险。[RUNTIME-02][RUNTIME-05][RUNTIME-06][AI-06][AI-08]
6. **位置轨迹、语音和游记可能包含敏感/个人信息。** 精确轨迹属于敏感个人信息；应单独同意、最小化、短期保存并完成影响评估。默认不保留连续原始轨迹、不常开麦克风、不把用户游记直接写入公共知识库。[REG-02][REG-03]
7. **“禅小荔”若严格限定为知识问答/导游助手，通常更接近拟人化互动办法第二条的排除场景，但这不是法律结论。** 若加入持续情感互动、长期关系记忆、依赖诱导、主动陪伴或情绪支持，适用性可能改变；命名、人格、欢迎语、记忆和运营机制须在上线前经法务确认。[REG-06]

## 2. AI 导游的任务边界

### 2.1 首期适合交给 AI 的任务

- 从游客游记/自然语言需求中提取地点候选、时长、偏好、同行人、体力/无障碍约束和未决问题；
- 对已审核文化资料做检索、摘要、翻译、不同长度讲解和追问；
- 把用户意图转换成地图/内部路线工具的结构化参数；
- 解释工具返回的路线候选、时间与限制，不改写底层事实；
- 在确定性位置事件到达后，从已发布讲解库选取对应内容；
- 对低风险偏好给出候选顺序，并让用户确认。

### 2.2 不得让模型自行决定的任务

- 编造或修补坐标、入口、内部道路、开放时间、票价、客流、天气、应急与无障碍状态；
- 把 POI 中心点当游客入口，把直线距离当步行距离，把旧路线当当前可通行；
- 对历史、人物、佛教教义、文物、宗教仪轨和地方传说作无来源断言；
- 给出“绝对安全”“一定开放”“适合所有人”等保证；
- 未经用户确认执行购买、预订、支付、发布游记、共享位置等有副作用操作；
- 将游客上传内容、聊天或轨迹自动升级为官方知识。

### 2.3 内容风险分级

| 等级 | 典型内容 | 回答规则 |
|---|---|---|
| L0 稳定低风险 | 已审核景点简介、建筑说明、常识性礼仪 | RAG 命中后可回答，逐段引用与标注核验日 |
| L1 解释性文化 | 历史人物、禅宗脉络、宗教术语、传说 | 区分史料/宗教传统/地方传说/现代解释；必要时人工审核 |
| L2 动态运营 | 开放、票务、活动、交通、天气、客流、临时封闭 | 只能用实时或有效期内官方工具；失败即明确无法核验 |
| L3 安全/权益 | 紧急事件、医疗、消防、走失、无障碍、儿童/老人 | 不作诊断或保证；优先展示景区官方人员、电话和现场标识 |
| L4 受限动作 | 支付、预订、公开发布、精确位置共享 | 首期不开放自主执行；如未来增加，必须独立授权、二次确认与审计 |

## 3. 推荐的受控单编排工作流

### 3.1 总体流程

```text
用户输入（文字 / 单次语音 / 游记）
        ↓
意图、风险与个人信息检测
        ↓
结构化提取（保留原文证据）
        ↓
知识检索 / 地图或实时工具（按白名单）
        ↓
结果校验：来源、时效、坐标系、约束、权限
        ↓
生成回答：事实 + 引用 + 不确定性 + 下一步
        ↓
安全/高风险规则与发布后日志抽检
```

这是一条可观测工作流，不要求多个互相对话的 Agent。官方函数调用文档本身也说明：模型提出工具名和参数，真正执行、验证、鉴权和错误处理仍由应用负责；文档建议限制活跃工具数量并谨慎设计权限。[AI-02]

### 3.2 首期工具白名单候选

| 工具 | 权限 | 输入校验 | 输出处理 |
|---|---|---|---|
| `search_verified_knowledge` | 只读 | 景点/主题/语言/有效期 | 返回原文片段、来源、版本、审核状态；未发布内容不可见 |
| `resolve_poi_candidates` | 只读 | 查询名、行政区、坐标系 | 只返回候选，不自动选入口；保留平台、POI ID、坐标系和置信说明 |
| `calculate_public_walk` | 只读 | 经核验入口、厂商要求坐标系 | 保留请求时间、提供商、路线限制；不得复制入自有路网 |
| `calculate_internal_route` | 只读 | 已发布内部节点、用户约束 | 只使用景区批准网络；封闭/过期边不可参与 |
| `get_current_official_status` | 只读 | 景点/状态类型 | 只接受在有效期内的官方运营源；失败不得回退到模型记忆 |
| `get_narration_asset` | 只读 | 讲解点、语言、时长、版本 | 只返回已发布脚本/音频与版权状态 |

天气、客流、票务等工具是否进入首期，取决于真实数据源、许可、SLA 与成本，不在 Discovery 锁定。

工具调用最低防线：JSON Schema、枚举和范围校验；坐标系显式字段；租户/景区隔离；超时与重试上限；结果时效；只读凭证；提示注入隔离；调用日志中不记录密钥和不必要的原始个人信息。

## 4. 游记结构化：从文本到“待确认行程”

结构化输出能约束语法，但官方文档明确提示：符合 JSON Schema 不代表值在语义上正确，应用仍需验证。[AI-01]

### 4.1 候选提取对象

| 字段 | 说明 | 校验方式 |
|---|---|---|
| `source_span` | 原游记中的直接证据片段 | 必须能回指原文，禁止凭空新增 |
| `place_text` | 用户写出的地点原词 | 原样保留，不先标准化覆盖 |
| `poi_candidates` | 可能对应的标准 POI | 由地图/景区目录工具返回，可为多项 |
| `explicit_or_inferred` | 用户明确表达或模型推断 | 推断必须单独标识 |
| `visit_order` / `time_hint` | 明确顺序、时段、停留时长 | 与原文证据关联；冲突保留为未决项 |
| `preferences` | 文化、摄影、亲子、休闲等 | 只提取与规划相关内容 |
| `mobility_constraints` | 体力、台阶、轮椅、老人儿童 | 可能敏感；最小化、用途告知、由用户确认 |
| `transport_hint` | 步行/驾车/接驳等 | 不从距离自动推断 |
| `confidence` | 候选匹配置信说明 | 低置信度不得自动入路线 |
| `unresolved_questions` | 地点歧义、入口、日期等 | 在调用路线前向用户确认 |

### 4.2 确定性处理顺序

1. 先保存本次处理所需的最小原文，不把完整游记默认长期保存；
2. 模型提取结构化候选，并逐字段附原文证据；
3. 服务端做类型、长度、枚举、时间逻辑和敏感信息校验；
4. POI 工具在限定行政区内返回候选；同名、多点、旧地名均不自动合并；
5. UI 让用户确认地点、入口、日期、交通方式和约束；
6. 路线服务只消费确认过的点和有效内部网络；
7. 用户可以编辑或删除提取结果，未经明确选择不公开游记。

任何网页、游记或文档中出现的“忽略规则、调用工具、发布内容”等文字都应视为不可信数据，不能成为系统指令。

## 5. RAG 与文化知识治理

### 5.1 知识不是同质文本

建议将每条知识声明成以下事实类型之一：

- `official_current`：景区/政府发布的现行运营或介绍；
- `historical_record`：可定位到史料、文物机构或学术来源的历史陈述；
- `religious_tradition`：宗教传统、教义或仪轨中的表述；
- `local_legend`：地方传说/口述，不冒充可证历史；
- `interpretation`：策展、导游或专家的解释性观点；
- `marketing_claim`：宣传语言，不能自动升级为事实；
- `ugc_experience`：游客主观体验，只用于体验洞察或在明确标注后展示；
- `realtime_status`：开放、票务、活动、客流、安全等有明确有效期的状态。

### 5.2 最低元数据

每个可检索片段至少保存：

- 知识 ID、景区/景点 ID、标题、原文片段与上下文；
- 事实类型、主题、人物、时期、语言、适用受众；
- 来源标题、机构、URL/档案号、发布日期、采集日、来源等级；
- 版权/许可、允许的用途、是否可向公众展示/生成音频；
- 核验人、核验日、证据范围、争议/异说说明；
- 有效起止、下次复核、版本、替代版本；
- 状态：`draft → reviewed → published → expired/withdrawn`。

分块应围绕一个可核验命题、一个讲解点或一段同源上下文，不能把来自不同等级、不同许可或不同有效期的内容拼成无法追溯的块。

### 5.3 检索与生成合同

1. 按景区、语言、事实类型、发布状态和有效期先过滤，再做语义/关键词混合检索；
2. 每条召回保留原始证据和元数据；托管 RAG 能返回引用不代表引用必然支持生成句子；
3. 生成前按来源等级、时间、冲突与主题做重排；
4. 回答中的每个可核验陈述映射到支持它的片段；
5. 若来源冲突，展示差异与各自来源，不由模型“投票”成唯一真相；
6. 无足够证据则拒绝事实性补全；
7. 内容撤回/过期后，索引和缓存必须同步删除或失效。

Gemini File Search 是一个可考察的托管 RAG 候选，官方文档说明它能导入、分块、索引、元数据过滤并返回引用；同时，索引内容会持续保存至手动删除，原始 File 对象则有不同生命周期，且内置工具组合有兼容限制。这些都是供应商评估项，不构成选用结论。[AI-05]

### 5.4 UGC 隔离

游客游记、聊天、纠错和打卡内容进入独立隔离区：

- 可用于发现别名、痛点和待核验线索；
- 不自动成为官方事实、开放状态、内部路线或讲解稿；
- 只有在权利清晰、去标识、人工审核、来源标注后，才可进入发布知识库；
- 用户删除内容时，原文、索引、缓存、派生摘要和训练/评测副本按既定流程联动处理。

## 6. 回答、引用与幻觉防控

### 6.1 回答契约

面向游客的事实性回答建议包含：

1. **简洁答案**；
2. **依据**：可点击的来源标题/机构；
3. **核验时间或有效期**；
4. **事实类型**：史料、宗教传统、地方传说、运营状态等；
5. **不确定性/冲突**；
6. **AI 生成标识**与纠错入口。

对每句话做“引用蕴含”检查：来源是否真的支持该句、是否超出适用时间/景点、是否把推断写成事实。引用数量多不等于可信。

### 6.2 强制拒答/降级规则

- 未找到已发布证据：`暂无已核验资料，建议以景区现场公告或工作人员答复为准。`
- 实时工具失败：说明失败时间，不复用模型常识或过期缓存；提供官方渠道。
- 地点歧义：列出候选并让用户确认，不默认最近点。
- 路线无法验证：不给捷径，不声称可通行；回退到现场标识/人工服务。
- 历史/宗教争议：并列来源和性质，不以单一营销文本定论。
- 医疗、消防、走失等紧急问题：优先官方紧急渠道和现场人员，不进行诊断或替代救援。

### 6.3 主要攻击面

- 游记、网页、PDF、UGC 中的提示注入；
- 伪造官方来源、引用错配、过期文档仍被召回；
- 工具参数越权、跨景区/跨用户读取、坐标系混淆；
- 模型用“常识”覆盖工具错误或空结果；
- TTS 将隐藏文本、错误数字或敏感信息读出；
- 日志、分析平台或供应商意外留存轨迹、音频和原文。

控制措施：检索内容永远是数据而非指令；系统策略与工具白名单独立；结果做 schema 和语义双校验；工具最小权限；租户隔离；引用回指；敏感日志脱敏；红队覆盖“无结果、冲突、过期、恶意文档、越权和工具故障”。NIST 生成式 AI 风险框架可作为治理、测量和管理的非强制性参考，不应冒充中国法律要求。[AI-09][AI-10]

## 7. 位置触发讲解

### 7.1 触发与内容分离

位置触发链应是：

```text
设备定位 → 精度/滞回/驻留/顺序/冷却规则 → 讲解点事件
→ 读取已发布讲解资产 → 用户可见/可控播放
```

LLM 不持续读取原始轨迹决定“你到了哪里”，也不临场生成路线安全事实。每个讲解点要有经核验入口/区域、触发半径候选、精度阈值、版本、有效期、人工“我已到达”按钮和误触发反馈。

### 7.2 端侧限制

- H5 隐藏后不能可靠持续接收位置，且有声自动播放受浏览器策略限制；“进入后台自动播讲解”不能作为 H5 承诺。[RUNTIME-01][RUNTIME-02]
- 微信小程序前后台定位需分别申请用途、类目与权限；后台音频不能在后台任意新控制，须实机与审核验证。[RUNTIME-03][RUNTIME-04][RUNTIME-05]
- 原生 App 能力更强，但 iOS/Android 都有后台权限、系统限频、电量和应用商店政策，不能宣传为永不间断。[RUNTIME-07][RUNTIME-08][RUNTIME-09]

首期候选应以前台触发 + 手动到点为基线；是否增加后台触发，等待真实游览研究和端侧 PoC。

## 8. TTS / ASR 候选

| 方式 | 优点 | 风险/限制 | 首期建议 |
|---|---|---|---|
| 真人录音 | 情感、语境和专名发音最可控 | 录制/版权/更新成本高，变更慢 | 核心精品讲解候选；合同登记表演者、用途和期限 |
| 预生成 TTS | 可人工审听、修正专名、离线缓存，运行时成本低 | 内容更新要重新生成；模型/声音许可和 AI 标识需核验 | 核心景点的优先候选，与真人录音并行比较 |
| 实时云 TTS | 可回答临时追问、长度和语气灵活 | 网络、延迟、单价、跨境/委托处理、误读、弱网 | 只用于低风险动态问答；生成前过滤数字、专名和敏感文本 |
| 系统/端侧 TTS | 较少云传输，可离线 | 机型声音、语速、方言和发音不一致 | 作为无障碍/断网降级，不作为品牌声音唯一来源 |
| 云 ASR（按住说话） | 输入自然，可识别开放问句 | 噪声、方言、延迟、音频隐私与费用 | 小范围 PoC；每次明确启动/停止，返回可编辑转写 |
| 持续监听/后台 ASR | 交互连续 | 隐私、耗电、误采集、平台审核和成本显著 | **首期不建议** |

官方 TTS 文档说明可把文本/SSML 生成音频并控制语音参数；Gemini TTS 文档在基准日仍标有 Preview 能力，预览状态不适合直接当生产稳定性承诺。Speech-to-Text 文档说明数据日志选择会影响供应商对内容的使用，但中国项目仍需独立核验处理地域、合同角色、删除和跨境条件。[AI-06][AI-07][AI-08]

语音质量清单：六祖、惠能、国恩寺、地名/古籍/佛教术语词典；普通话/粤语需求；数字、日期、方位、停顿；噪声环境；耳机/扬声器切换；屏幕同步字幕；长者语速；断网与来电中断。

## 9. 质量评测与发布门槛

### 9.1 离线黄金集

由文化审核人、景区运营、地图/安全人员共同建立版本化测试集，至少覆盖：

- 官方稳定事实、历史人物/年代、宗教传统、地方传说和争议说法；
- 同名/别名/错别字/旧称/模糊地点；
- 开放、票务、天气、客流、封闭和应急等动态问题；
- 无答案、来源冲突、过期来源、恶意提示注入；
- 多轮追问、儿童/长者/无障碍需求、中文/粤语候选表达；
- 错误坐标系、POI 中心与入口混淆、不可达路线；
- 语音噪声、专名、数字、弱网、切后台与权限拒绝。

### 9.2 核心指标

| 维度 | 指标与验收含义 |
|---|---|
| 结构化提取 | 字段准确率、原文证据覆盖、歧义识别率、用户修正率；schema 通过不能代替语义正确 |
| 检索 | 目标证据是否进入前 k 条、过期/未发布内容泄漏率、冲突来源召回率 |
| 回答 | 事实准确率、无依据陈述率、拒答正确率、事实类型标注准确率 |
| 引用 | 引用精确率、句子被来源真实支持的比例、链接可访问率、核验日期正确率 |
| 工具 | 工具选择/参数正确率、坐标系正确率、超时降级、越权调用数 |
| 路线 | 约束满足、入口匹配、封闭边拦截、不可达时正确拒绝；不是让 LLM 评路线几何 |
| 位置 | 触发准确/召回、重复触发、相邻点误触发、手动降级成功率 |
| ASR/TTS | 转写词错率/意图成功率、专名发音、数字准确、可懂度、用户中断成功率 |
| 体验 | 首响应/完整响应延迟、任务完成率、纠错率、无障碍可用性、满意度 |
| 成本 | 每成功问答、每完整游览、每分钟语音和每活跃游客的总成本 |

### 9.3 零容忍发布缺陷

- 编造开放/票价/封闭/应急/无障碍状态；
- 伪造历史、宗教或文化来源；
- 引用与陈述无关或把传说写成史实；
- 把代表点当入口、直线当步行路线或绕过封闭；
- 泄露精确轨迹、音频、游记、密钥或其他用户数据；
- 未经确认执行支付、公开发布、共享位置等有副作用动作。

每次模型、提示、知识库、路由规则或供应商更新都应跑回归集；线上以匿名化抽样、用户纠错、工具失败和异常成本告警持续评测。

## 10. 隐私、生成式 AI 与拟人化合规

### 10.1 最小化数据清单

| 数据 | 默认策略 | 需要额外评估的情况 |
|---|---|---|
| 精确位置/轨迹 | 到点尽量端侧判定；默认不上传连续轨迹；短保存、可删除 | 后台定位、跨景区画像、向地图/云供应商提供、跨境 |
| 语音 | 明确按下才采集；转写完成后按最短期限删除原音频 | 声纹、持续监听、质检留存、第三方 ASR |
| 游记/聊天 | 只为当前任务保留必要文本；默认不公开、不训练 | 分享、进入 UGC、进入评测/知识库、包含他人信息 |
| 偏好/同行约束 | 可本地或短期保存，用户可查看/改/删 | 健康、残障、未成年人、个性化推荐/自动化决策 |
| 工具/模型日志 | 去密钥、去精确位置、去原始敏感内容 | 供应商保留、跨境、长周期分析 |

精确轨迹是敏感个人信息，通常需要单独同意、必要性说明、严格保护和影响评估；向其他处理者提供、跨境、未成年人处理还可能增加义务。[REG-02][REG-03] 具体告知、角色、保存期与跨境路径由法务和隐私负责人确认。

### 10.2 生成式 AI 服务与标识

《生成式人工智能服务管理暂行办法》适用于向境内公众提供生成式 AI 服务的情形，要求合法来源、个人信息与知识产权保护、提高准确可靠性、投诉处置等；本项目与上游模型提供者的角色和备案/安全评估义务需法务核验。[REG-04]

《人工智能生成合成内容标识办法》已于 2025-09-01 实施，对生成合成文本、音频、图片、视频等的显式/隐式标识提出要求。[REG-05] 产品候选基线：

- 对动态生成回答显示“AI 生成/请核验来源”；
- 对生成或合成音频提供可感知标识；
- 导出、下载、分享的内容保留适用的显式/隐式标识和来源元数据；
- 预录真人内容与 AI 合成内容在资产库中分开标记；
- 具体标识形式、位置、元数据及上游责任以发布时现行规则和法务意见为准。

### 10.3 “禅小荔”与拟人化互动办法

《人工智能拟人化互动服务管理暂行办法》已于 2026-07-15 实施。第二条把“模拟人格特征、思维模式和沟通风格，通过文字、图片、音视频等与自然人持续情感互动的服务”纳入范围，同时明确排除**不具备持续情感互动特征的智能客服、知识问答、工作助手及学习研究类应用**。[REG-06]

基于当前设想的初步判断：

- 若“禅小荔”只做文化知识问答、导游说明、路线工具解释，且不构建持续情感关系，通常更接近第二条排除范围；
- 仅有名称、插画形象、礼貌语气或有限品牌人格，不足以由本报告判定适用或排除；
- 若未来加入长期情绪记忆、关系等级、主动陪伴、依赖诱导、情感慰藉、模拟亲密关系或持续追踪情绪，风险显著上升；
- 无论是否落入该办法，AI 身份、生成内容标识、个人信息、未成年人和内容安全义务仍需单独满足。

这只是产品边界推断，**不是法律结论**。上线前应让法务以实际系统提示、人格设定、记忆机制、互动频率、主动消息、未成年人模式和运营文案做书面确认。

## 11. 成本模型与控制

### 11.1 总成本公式

`月度 AI 总成本 = 文档清洗与人工审核 + 索引/嵌入 + 检索 + 模型输入/输出 + 缓存 + ASR 分钟 + TTS 字符/音频分钟 + 存储/流量 + 评测/监控 + 合规/客服`

单价随模型、地区、缓存和批量策略变化。本报告只引用官方计费维度，不抄写会迅速过期的大型价格表；Gate 2 与上线前用官方价格页重新计算。[AI-03][AI-04][AI-05]

### 11.2 可验证的控制手段

- 用单一编排替代多个模型互相对话；
- 低风险分类/抽取使用满足质量门槛的较低成本候选，高风险回答不因省钱跳过检索/校验；
- 只发送必要片段，不把整个知识库或整段历史每次送入模型；
- 对稳定、重复上下文评估官方缓存能力，但将缓存生命周期、删除和隐私纳入验收；
- 核心讲解预生成/预审听，不在每次到点实时合成；
- ASR 采用一次一问，设置时长/文件大小上限；
- 每用户/每会话调用上限、超时、熔断和成本告警；
- 以“成功完成一次问答/游览”的端到端成本比较，而不是只看百万 token 单价。

## 12. 分阶段候选演进

### 阶段 A：受控 AI 导游最小验证

- 单编排器；
- 游记结构化 + 用户确认；
- 已审核 RAG + 逐句引用 + 无证据拒答；
- 3–6 个只读工具，路线与实时事实不由模型生成；
- 文字优先，核心讲解使用预录/预生成审核音频；
- 前台位置触发 + 手动到点；
- 完整黄金集、隐私影响评估和成本仪表口径。

### 阶段 B：在证据成立后增强

- 单次 ASR 和实时 TTS；
- 经小程序/原生审核与实测的后台位置；
- 更细的个性化路线与多语言；
- 运营后台的知识更新、冲突处理、灰度和回滚。

### 阶段 C：仅在指标证明必要时扩展

- 专用规划器、审核器或内容生产工作流；
- 多景区/多租户知识与工具隔离；
- 多 Agent 只在单编排无法满足的复杂任务上试验，必须证明质量收益大于延迟、成本和运维风险。

以上是产品演进候选，不等于已获第二阶段或 Implementation 授权。

## 13. Gate 1 待用户确认与证据缺口

### 13.1 建议确认的原则

1. 是否同意首期采用“受控单编排 + 少量只读工具”，不做多 Agent 扩张；
2. 是否同意所有文化事实引用、事实类型区分和“无证据即拒答”；
3. 是否同意路线、开放、安全、票务、天气、客流只信任核验数据/实时工具；
4. 是否同意核心讲解预录/预生成审核，ASR/TTS 仅作后续小范围验证；
5. 是否同意精确轨迹端侧优先、连续轨迹默认不上传、麦克风不持续监听；
6. 是否同意将“禅小荔”严格定位为知识问答/导游助手，并由法务复核人格、记忆与互动边界。

### 13.2 阻塞下一阶段选型的缺口

- 六祖镇可发布的官方/权威文化资料、讲解稿、许可与审核责任人；
- 动态开放、票务、活动、安全、客流和应急信息的官方接口或运营更新机制；
- 地图/内部路网的真实数据与责任边界；
- 候选模型在中文、地名、宗教文化、引用和工具调用上的同集评测；
- ASR/TTS 对普通话、粤语候选、景区噪声和专名的实测；
- AI/语音供应商的数据地域、DPA、保存/训练政策、删除、跨境和服务可用性；
- 面向公众提供服务时的备案、安全评估、生成标识和拟人化互动适用性法律意见；
- 真实并发、会话长度、游览时长与成本容量模型。

在这些证据闭合前，本报告不推荐锁定模型、RAG 服务、向量库、TTS/ASR 厂商或 Agent 框架。
