# 登录注册页产品需求文档 (04-auth-page-prd.md)

## 1. 产品背景与目标
- **核心诉求**：优化 `/account` 路由下的游客账号登录与注册页面，使其具有契合“云游地图”文旅品牌的美学质感与流畅体验，同时严格继承现有安全鉴权后端。
- **目标指标**：
  1. 延续“地图文旅”视觉符号，桌面端采用“品牌意境/地图探索区 + 现代化表单卡片”双栏，移动端平滑折叠为单栏；
  2. 支持 `redirect` 来源参数，登录或注册成功后能够自动回跳至用户原先被拦截的页面（如规划、社区、行程等）；
  3. 提供“暂不登录，返回地图”快捷通道；
  4. 表单具备完备的实时格式校验、加载禁用态、防重复点击、密码显隐切换及焦点无障碍支持。

---

## 2. 功能范围与交互规范

### 2.1 鉴权协议与字段要求（严格保持现有接口契约）
- **账号名 (`handle`)**：
  - 格式：3~32 位字母、数字、下划线、短横线；
  - 自动 trim 并转换为小写提交。
- **口令 (`passphrase`)**：
  - 长度：至少 12 字符，最长 128 字符；
  - 注册模式下必须二次确认 (`confirmation`)。
- **服务端接口**：
  - `POST /api/v1/auth/login` (Body: `{ handle, passphrase }`)
  - `POST /api/v1/auth/register` (Body: `{ handle, passphrase }`)
  - `POST /api/v1/auth/logout` (Body: `{}`)
  - `GET /api/v1/auth/me` (用于初始化鉴权状态)
- **安全与合规**：
  - 密码不打印在控制台，不存入 localStorage；
  - 失败提示概括化，防用户枚举；
  - 遵守安全 Cookie 策略。

### 2.2 视觉与状态设计
1. **未登录状态**：
   - 顶部清晰 Toggle（“登录” / “建立账号”）；
   - 左侧展示新兴六祖景区意境画面、核心优势（“无需手机号与邮箱”、“会话安全加密”、“仅在跨设备分享时需要”）；
   - 右侧表单提供聚焦高亮、错误文本靠近输入框、密码一键显示/隐藏功能。
2. **已登录状态**：
   - 显示当前游客 Handle、会话到期日、只读分享能力生效状态；
   - 提供“进入地点社区”、“我的旅程”、“安全退出”操作。
3. **回跳与导航链路**：
   - 支持 URL Query `?redirect=/journey` 或 `?redirect=/community`；
   - 登录成功后若存在合法相对路径 `redirect`，延时 500ms 友好提示后自动跳转，否则停留在当前状态或引导至地图。

---

## 3. 非目标 (Non-Goals)
1. 不添加虚假的微信/QQ/手机短信验证码登录（未配置后端能力不伪造）；
2. 不修改 Cookie 鉴权与 Session 存储结构；
3. 不破坏已有的离线本地旅程读取机制。
